# 学生端桌面客户端

机房里发一个 exe，学生输考号就能考试。**操作题在真实的资源管理器 / 记事本 /
WPS 里做**，交卷时程序拍一份考试文件夹的快照传回教师端，服务器按检查点自动判分。

这不是另一套系统，是**这套系统的另一个客户端**。学生、班级、试卷、考试全部来自
后端那一个库；交卷走的还是网页端本来就有的那个接口。所以判分、成绩页、阅卷界面、
成绩导出，后端一行都没改。

```
老师：网页后台组卷 → 发布考试（选班级）
                         ↓
学生：双击 exe → 输考号 → 服务器认人 → 列出我的考试 → 取卷 → 真机操作 → 交卷
                         ↓
老师：成绩页实时看到，操作题每一问过没过都写着
```

---

## 怎么跑起来

### 老师（一次性）

在网页后台正常组卷、发布考试，**选好目标班级** —— 那就是学生端的准入名单。
不用导出任何文件。

### 机房装机（一次性）

**只发 `考试客户端.exe` 一个文件。** 拷到学生机任意位置（桌面就行），双击即可 ——
不用安装、不要管理员权限、**exe 旁边不生成任何文件**。设置和答案备份写在
`%LOCALAPPDATA%\信息技术考试客户端\`，所以 exe 放在只读位置（网络共享、被组策略
锁住的桌面）也照样能跑。

教师端地址三种带法，任选一种：

| 带法 | 怎么做 | 适合 |
|---|---|---|
| **烤进 exe** | `python build.py --server 192.168.1.8:8080` | 机房统一装机，学生双击就能用 |
| **写在文件名里** | 把 exe 改名成 `考试客户端@192.168.1.8_8080.exe` | 教师端换了 IP，**改个名就行，不用重新打包**（冒号在文件名里非法，端口前用下划线） |
| **学生输一次** | 登录页填 `192.168.1.8:8080` | 临时用一台机器 |

三者同时存在时：**文件名 > 本机保存 > 烤进去的**（命令行 `--server` 比这三个都高）。
文件名排在保存值前面是故意的 —— 网管刚改的名是最新的决定，不该被各机器上那个过期
的保存值顶掉。

### 学生

输考号姓名 → 登录 → 选考试 → 考 → 交卷。就这些。

交完卷**考场自动清空**：还开着的考试文件会被强制关掉（只认标题里带考试文件名的
窗口，资源管理器只关不杀），文件夹抹干净，下一位考生直接开考。开考前也会先清
一次 —— **每场考试都是全新环境**。

## 目录

```
client/
  api.py        和教师端说话：探活、认人、取卷、交卷（只用标准库 urllib）
  snapshot.py   给真实文件夹拍快照（操作题判分的依据）
  package.py    考试包 .ekb / 答案包 .ans 的读写
  store.py      本机存的四样：教师端地址、答题草稿、待补传清单、考试记录
                （都写在 %LOCALAPPDATA%，不写在 exe 旁边）
  ui.py         Tkinter 界面：登录 → 首页 / 考试 / 打字练习
  exam_ui.py    答题页和交卷页
  states.py     交卷时按题型收集本机状态（判分依据）
  docx.py       读 .docx 里的 XML —— WPS 文字题的自动判分靠它
  cleanup.py    考完清场：强制关掉还开着的考试文件，抹干净文件夹
exam_client.py  入口，打包成 exe 的就是它
build.py        打包脚本（打哪个系统由它选用的 Python 决定）
tests/          端到端自检：起一个真后端，走完整条链路
```

后端那一半在 [`backend/app/routers/desk.py`](../backend/app/routers/desk.py)，
四个接口：

| 接口 | 干什么 |
|---|---|
| `GET /api/desk/ping` | 探活。开考前让监考老师知道网通不通 |
| `POST /api/desk/signin` | 报考号姓名 → 认人 → **只给他自己班的考试** |
| `GET /api/desk/exam/{口令}` | 取卷：下载这场考试的 .ekb（没有答案） |
| `GET /api/desk/export/{id}` | 老师手工导包，给没网的考场留的后路 |

交卷复用 `POST /api/take/{口令}/submit` —— 网页端本来就有的那个。

## 兼容 Win7 / 8 / 10 / 11

PyInstaller 打出来的 exe 带着**打包时那个 Python 的运行时**，目标系统的下限就是
那个 Python 的下限：

| 打包用的 Python | exe 能跑在 |
|---|---|
| **3.8**（最后一个支持 Win7 的） | **Win7 SP1 / 8 / 8.1 / 10 / 11** |
| 3.9 ~ 3.12 | Win8.1 / 10 / 11 |
| 3.13+ | Win10 / 11 |

**换目标系统不用改一行代码**，换个 Python 重跑 `build.py`：

```bash
python build.py                                      # 用当前 Python
python build.py --python D:\Python38-32\python.exe   # 覆盖到 Win7
```

要覆盖 Win7 就装 Python 3.8.10（最后一个带 Windows 安装包的 3.8），**挑 32 位
那版**：32 位 exe 在 32 位和 64 位 Windows 上都能跑，机房里总有几台老机器。

Win7 上另外两件事：机器得打了 SP1 和 KB2999226（通用 C 运行库），否则双击没反应
也不报错；杀软容易拦没签名的单文件 exe，先加白名单，或者用 `--onedir` 打成文件夹。

程序本身只用 Python 标准库（Tkinter + urllib + zipfile），没有第三方依赖，
所以换 Python 版本重打不会有兼容问题。

## 部署到服务器之后，学生端怎么连

能连。学生端走的是普通 HTTP，和浏览器访问同一个地址、同一个端口 —— **网页打得开，
exe 就连得上**。

| 部署方式 | 学生端「教师端地址」填什么 |
|---|---|
| `docker compose up`（默认） | `服务器IP:8080`　—— 就是 `WEB_PORT` 那个端口 |
| 改了 `WEB_PORT=80` | `服务器IP`　—— 80 端口可以不写 |
| 挂了域名和证书 | `https://exam.xxx.edu.cn`　—— **https 要自己写上**，不写会按 http 走 |
| 开发时直接跑后端 | `服务器IP:8000` |

`frontend/nginx.conf` 已经把 `/api/` 转给后端，`client_max_body_size 30m`、
读写超时 120 秒都配好了 —— 交卷要传整份文件夹快照，这两项是关键，别调小。

部署时顺手把 `PUBLIC_BASE_URL` 填成对外地址（`.env` 里），导出的考试包才会带上
正确的服务器地址；不填也不影响，学生端自己填的地址优先。

几个会卡住的地方：

- **防火墙**：服务器要放行那个端口。装完先在一台学生机上用浏览器打开试试。
- **自签证书**：学校自己签的 https 证书过不了校验，学生端会直说
  「证书通不过校验，请改用 http 地址」，不会只丢一个看不懂的英文错误。
- **地址填错**：点「登录」当场就会说连不上，不会等到交卷才发现。也可以用下面的
  自检命令批量查。

## 装机排障

机房里挨台开窗口看那行小字太慢。exe 自带一个不开窗口的自检：

```bash
考试客户端.exe --selftest 检查结果.txt --server 192.168.1.8:8000
```

它把该导的模块导一遍、真建一次窗口、真发一次 HTTP、真拍一次快照，最后真去连
一次教师端，结果写进那个文件，退出码 0 表示程序本身没问题。

报告最后还会写明**这台机器会连哪儿**，三个来源各是什么：

```
教师端地址：http://111.170.33.3:3315
    文件名 111.170.33.3:3315　｜　本机记录 无　｜　打包内置 111.170.33.3:3315
```

装机时最常被问的就是这一句。网管改了 exe 文件名、而某台机器上还留着上学期的
记录 —— 这种对不上的情况，看这一行就清楚了。

`build.py` 打完包会自动跑一次，**过不了就不出包** —— 见下面「踩过的坑」里
那条 email。

## 自检

起一个真后端（临时 SQLite、随机端口），走完整条链路 —— 真 HTTP、真文件操作、
真 Tk 窗口：

```bash
backend\.venv\Scripts\python.exe -m pytest desktop/tests -q
```

`test_flow.py` 管链路，`test_ui.py` 管界面，`test_three_kinds.py` 管三类操作题的
自动判分，`test_single_exe.py` 管"只发一个 exe"那几条（写哪儿、地址从哪来、打包
写的文件名客户端读不读得回来）。**"能 import"证明不了界面能用**：
上一版就出过组件因为初始化顺序一加载就崩、编译和测试全过的事，所以这里真的
`Tk()`、真的点按钮。

## 设计上的取舍

**客户端不判分。** 考试包里没有答案、没有检查点，客户端只做四件事：认人、取卷、
铺考场、交卷时拍快照。分数在服务端算 —— exe 能被反编译，把判分规则发到学生机上
等于发答案。

**判的是最终状态，不是操作步骤。** 新建文件夹用右键、菜单栏还是快捷键都算对。
这条从网页版继承过来，检查点语言一个字没改 —— 当初就是照着"断言最终状态"设计的，
换成真机只是换了状态的来源。

**本地 `.ans` 永远先写，再上传。** 断网、服务器没开、交卷那一下网线被踢掉，卷子
已经在硬盘上了，网通了补传。考场里最怕的不是慢，是丢卷。补传要用的东西（口令、
路径前缀、哪几题塞快照）全写在 `.ans` 里，所以**换台机器、隔一天也补得上**。

**真机操作意味着环境不可控。** 所以：考试文件夹固定 `C:\EXAM`，开考时清空重建
（清之前先去掉只读属性，否则上一场学生设的只读文件会让清空失败）；每次作答都写
草稿，断电重开能接着考。

**做不到的事，现在就说清楚：**

- **拖拽题、流程图题还不能在 exe 里作答**（题库里还有这么几道）。答题区先占着位置
  写明"本题在网页端作答"，不会让学生以为自己漏做了。
- **AI 工具题判的是"问得对不对"**：对话框嵌在答题界面里，检查点看学生有没有把题干
  要求的那几件事问出去。AI 答得好不好不计分 —— 那不是这道题要考的。
- **防作弊只做了最基本的**：全屏窗口、倒计时、自动交卷、关窗口要确认。深度的
  系统锁定（禁任务管理器、钩键盘）既脆弱又容易和杀软打架，没做也不建议做。
  考场纪律靠监考老师比靠软件实在。
- **回收站只认 Win7 及以后**（`$Recycle.Bin` 里的 `$I` 文件）。XP 的 `INFO2`
  是另一种格式；「删掉了」用「文件不在了」判就够。

## 踩过的坑（都已修，别再踩回去）

真机和多线程才会出的问题，仿真环境里一个都碰不到：

| 坑 | 后果 |
|---|---|
| **快照路径少了 `logical_root` 前缀** | 全班操作题判 0 分，而且原因是"找不到文件"，最难查。操作题集体 0 分先查它 |
| 从工作线程调 `widget.after()` | Tk 不是线程安全的，多半没事，偶尔一个没有栈的硬崩溃。现在工作线程只往队列里放结果 |
| GBK 内容被当 UTF-16 解成乱码 | 「文件里写上……」判不过，而且不报错 |
| 只读文件让考场清不干净 | 上一场学生设的只读文件，下一场布置考场直接失败 |
| 空文件夹没进 zip | 「在『会徽』文件夹中新建」—— 会徽根本没铺出来 |
| 答案包里没存口令 | 程序重开后补传，不知道该往哪交 |
| 重打包时把整个「发布」删了 | 收上来放在 `发布\答案包` 里的卷子跟着没了 |
| **打包时排除了标准库的 `email`** | exe 一开就死在 `urllib` 里 —— urllib 要用 email 组装 HTTP 头。**标准库一个都别排**，省那几百 KB 不值 |
| 拿"进程还活着"当启动成功 | `--windowed` 的 exe 崩了也会弹个报错窗，从外面看一模一样。所以改成让 exe **自己写一份自检报告**，打包脚本认这个 |
| 自检时 `capture_output` 接 exe 的输出 | onefile 的 exe 会再开一个子进程，管道握在孙子手里，超时杀掉儿子后还在等管道关闭 —— 恰好挂在它要拦的那种失败上 |
| 窗口程序里 `print` | `--windowed` 下 `sys.stdout` 是 `None`，一句 print 就抛异常 |
| 判断题 A/B 和「正确/错误」对不上 | 全班判断题判错。**按题型判，别按答案长什么样猜** |
| 单选框绑定空串 | Tk 的「第三态」：四个选项一进题全是实心黑点，学生以为自己选过了 |
| 草稿写在系统 TEMP 里 | 上一次跑留下的草稿会被这次恢复进来 —— 自检里要隔离掉 |
| 交完卷不清考场 | 下一位考生铺不进来（文件被 WPS 锁着），上一个人的答案还留在磁盘上 |
| 运行数据写在 exe 旁边 | 想只拷一个 exe 到桌面就做不到 —— 程序一跑就长出设置文件和答案包文件夹；exe 放在只读位置还会直接写失败 |
| 打包写文件名、客户端解析文件名 | 分处两个文件，改一头忘一头，症状是学生双击后地址栏空着，而打包过程一切正常。`test_single_exe.py` 守着这条往返 |
