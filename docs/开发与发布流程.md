# 开发与发布流程

加新功能、新页面时照这个走。目标是：**改动先在本地验证，服务器上只做拉取和重启**，
不在生产环境上改代码、调 bug。

---

## 一、总体循环

```
本地改代码  →  本地验证  →  提交推送  →  服务器拉取重建  →  线上验证
   ↑                                                        │
   └──────────────── 有问题就回滚 ───────────────────────────┘
```

**绝对不要**直接在服务器上用 `vi` 改代码。改了不进 Git，下次 `git pull` 会冲突或被覆盖，
而且没人知道线上跑的到底是哪个版本。

---

## 二、本地开发

### 起本地环境

Windows 双击 `一键启动.bat`，Linux/macOS 执行 `./start.sh`。

本地默认用 SQLite（`backend/.env` 里的 `DATABASE_URL`），**和服务器的 MySQL 完全隔离**，
随便改随便试，不会碰到线上数据。

- 前端 `http://localhost:5173`，改 `.vue` 文件**自动热更新**，不用重启
- 后端 `http://127.0.0.1:8000`，改 `.py` 文件 uvicorn 会自动重载
- 接口文档 `http://127.0.0.1:8000/docs`，新接口写完直接在这里点着试

### 加一个新页面（前端）

改这四个地方，缺一个页面就出不来：

| 文件 | 做什么 |
|---|---|
| `frontend/src/views/新页面.vue` | 页面本体 |
| `frontend/src/router.js` | 加一条路由 |
| `frontend/src/App.vue` | 顶部导航加菜单项 |
| `frontend/src/api.js` | 要调后端就加对应方法 |

> 学生用的页面记得在路由里标 `meta: { public: true, bare: true }`，
> 否则会被登录守卫拦住，而且会套上教师界面的框。参考 `/take/:token`。

### 加一个新接口（后端）

| 文件 | 做什么 |
|---|---|
| `backend/app/schemas.py` | 定义出入参 |
| `backend/app/routers/xxx.py` | 写接口。**新建文件的话要在 `main.py` 里 `include_router`** |
| `backend/app/services/xxx.py` | 复杂逻辑放这里，路由里只管协议 |
| `backend/tests/test_xxx.py` | 加测试 |

权限用现成的依赖：`Depends(get_current_user)` 要登录，`Depends(require_admin)` 要管理员。
学生用的公开接口两个都不要加（参考 `routers/take.py`）。

### 改数据库表结构

**一定要走 Alembic，不要手工改表。** 服务器上的表结构靠迁移脚本自动升级。

```bash
cd backend
# 1. 先改 app/models.py
# 2. 生成迁移脚本
.venv/Scripts/python.exe -m alembic revision --autogenerate -m "给题目加难度字段"
# 3. 打开 alembic/versions/ 下新生成的文件，确认它只改了你想改的东西
# 4. 本地应用
.venv/Scripts/python.exe -m alembic upgrade head
```

⚠️ **第 3 步不能跳过**。autogenerate 有时会生成多余的操作（比如把某个索引删了重建），
线上跑起来可能锁表或丢数据。

⚠️ **生成的迁移脚本必须提交进 Git**。忘了提交的话，服务器上 `alembic upgrade head`
不会创建新字段，但代码已经在用它了，直接报错。

## 三、提交前的检查

```bash
cd backend && .venv/Scripts/python.exe -m pytest -q
```

全绿才提交。改了考试相关代码，**特别确认 `test_answers_never_reach_the_student` 还过**——
这条保证答案不会泄漏给学生。

前端确认能构建（语法错误在开发模式下可能不报）：

```bash
cd frontend && npm run build
```

### 记一条更新日志（每次改动都要做）

改动是给人用的，所以每次改完要把「这次做了什么」写进更新日志，别让使用者去猜。
打开 `backend/app/changelog_seed.py`，在 `VERSIONS` 列表**最前面**加一个版本块：

```python
(
    "1.5.0",                       # 语义化版本：加功能升次版本号，只修 bug 升修订号
    date(2026, 9, 20),             # 发布日期，写实际日期
    [
        ("Added", "新加了什么功能，使用者能拿它做什么。"),
        ("Fixed", "修了什么毛病，原来会怎样。"),
    ],
),
```

变动类型只用这六种：`Added` 新增 / `Changed` 变更 / `Deprecated` 弃用 /
`Removed` 移除 / `Fixed` 修复 / `Security` 安全。同类的写在一起。

写完本地灌一次库确认没写错：

```bash
cd backend && .venv/Scripts/python.exe -m app.seed
```

灌库按（版本号 + 类型 + 内容）去重，可以反复执行。但**改写**一条已经入库的旧记录会被
当成新记录插进去，库里就留下两条 —— 已经发布出去的条目本来也不该再改措辞，确实要改
就上「更新日志」页面把旧的那条删掉。

临时性的小改动也可以不动代码，直接在网页「更新日志 → 添加记录」里写。

### 提交

```bash
git add -A
git commit -m "说清楚改了什么、为什么"
git push
```

## 四、服务器上发布

### 发布前先备份

**改数据库结构的时候尤其别省这一步。**

```bash
cd /opt/A_System_of_WFXXKJ_Simulating_Examination && sudo bash backup/backup.sh
```

### 按改动类型选命令

不是每次都要重新构建。三个目录是**挂载**进容器的，改了立刻生效：
`data/uploads/`、`config.yaml`、`legacy/`。

| 改了什么 | 命令 | 大概耗时 |
|---|---|---|
| 只改 `config.yaml`（题量、及格线、卷头等） | `sudo docker compose restart backend` | 几秒 |
| 只改 `.env`（端口、密码） | `sudo docker compose up -d` | 十几秒 |
| 改了后端 Python | `git pull && sudo docker compose up -d --build backend` | 1~2 分钟 |
| 改了前端 Vue | `git pull && sudo docker compose up -d --build frontend` | 2~3 分钟 |
| 前后端都改了 / 不确定 | `git pull && sudo docker compose up -d --build` | 3~5 分钟 |

最常用的就是最后一条：

```bash
cd /opt/A_System_of_WFXXKJ_Simulating_Examination && git pull && sudo docker compose up -d --build
```

**数据库迁移不用手动执行** —— 容器启动时 `entrypoint.sh` 会自动跑：

```
等待数据库就绪 → ensure_db → alembic upgrade head → seed → 题库检查 → 启动服务
```

### 发布后验证

```bash
sudo docker compose ps
```

三个容器都是 `running`，backend 是 `healthy` 才算好。然后：

```bash
sudo docker compose logs backend --tail=40
```

看到 `[start] 启动服务` 且没有 Traceback 就正常。

最后浏览器打开系统，**按 Ctrl+F5 强制刷新**（前端改动会因浏览器缓存看不到），
把新功能实际点一遍。

## 五、出问题怎么回滚

### 代码回滚

```bash
cd /opt/A_System_of_WFXXKJ_Simulating_Examination
git log --oneline -5          # 找上一个好的提交
git checkout <提交号>
sudo docker compose up -d --build
```

修好之后回到最新：`git checkout main && git pull`。

### 数据库回滚

**代码回滚了但表结构没回滚**，往往还能跑（多出来的字段不影响旧代码）。
真要退表结构：

```bash
sudo docker compose exec backend alembic downgrade -1
```

⚠️ `downgrade` 会**删掉那次迁移加的字段和数据**，删了就没了。
所以发布前的那次备份很重要。

### 最坏情况：从备份恢复

```bash
cd /opt/A_System_of_WFXXKJ_Simulating_Examination
gunzip -c backup/db_2026-09-07_0200.sql.gz | sudo docker compose exec -T db \
  mysql -u root -p"$(grep '^MYSQL_ROOT_PASSWORD=' .env | cut -d= -f2)" \
  --default-character-set=utf8mb4 exam
sudo docker compose restart backend
```

## 六、几条经验

**发布挑没人用的时候。** 重新构建期间服务会中断几十秒到几分钟，
考试进行中发布会让学生的答题页断掉。

**一次只发一件事。** 同时改五个功能，出问题不知道是哪个引起的。

**改配置优先于改代码。** 加知识范围、改默认题量、改及格线这些，
`config.yaml` 或 `dict_items` 表里就能改，不用发版。

**服务器上的 `.env` 不进 Git**，`git pull` 不会动它。改端口密码直接在服务器上改。

**前端改动记得让用户强刷。** 浏览器会缓存旧的 JS，
你自己看到新版本了不代表别人也看到了。
