# 部署到有公网 IP 的机器

面向的场景：把项目搬到一台能被外网访问的电脑/服务器上，让全校师生用。

> 只是换台自己电脑单机用？不用看这篇，直接 `git clone` 后双击 `一键启动.bat`（Linux/macOS 用 `./start.sh`）。

---

## 一、先回答：能直接用吗

**不能。** 代码不用改一行，但有 **3 个默认值必须改**，否则等于门户大开。

| 项 | 默认值 | 不改的后果 |
|---|---|---|
| `JWT_SECRET` | `change_this_...` | 这串值公开在 GitHub 上，**任何人都能伪造管理员令牌**直接登入 |
| `ADMIN_PASSWORD` | `admin123` | 公网扫描器几分钟内爆破，对方能看到全部题目和答案 |
| `MYSQL_PASSWORD` | `exam_pwd` | 数据库口令公开 |

项目里带了自检脚本，改完跑一遍确认：

```bash
python backend/tools/check_deploy.py
```

它会把没改的默认值全部揪出来，并顺便生成一串安全的随机密钥。退出码 0 才可以部署。

### 架构上已经准备好的部分

这些不用你操心：

- 前端请求走相对路径 `/api`，**换任何 IP 或域名都不用改代码、不用重新构建**
- 学生答题链接用 `location.origin` 拼，自动跟着实际访问地址走
- MySQL 只在 Docker 内网，**没有暴露到宿主机**，外网连不到数据库
- 对外只开一个端口（默认 8080）

## 二、新机器要装什么

**走 Docker 的话，只装 Docker 一个东西。** Python、Node、MySQL、Nginx 全在镜像里，宿主机一个都不用装：

| 容器 | 镜像自带 |
|---|---|
| backend | `python:3.12-slim` + 13 个依赖包 |
| frontend | `node:20-alpine` 构建 → `nginx:1.27-alpine` 托管 |
| db | `mysql:8.0` |

下载地址：Windows/macOS 用 [Docker Desktop](https://www.docker.com/products/docker-desktop/)（免费）；
Linux 用 `curl -fsSL https://get.docker.com | sh`。

> Windows 装 Docker Desktop 有两个前提，新手最容易卡在这里：
> 需要 **WSL2**（安装程序会引导安装），以及 **BIOS 里开启虚拟化**。

**磁盘**：实测镜像共约 1.06 GB —— `mysql:8.0` 799MB、后端 210MB、前端 50MB，建议留 3GB 余量。

**国内网络**：拉镜像慢的话在 Docker Desktop → Settings → Docker Engine 加镜像加速：

```json
{ "registry-mirrors": ["https://docker.m.daocloud.io"] }
```

项目代码的构建已经用了国内源（pip 走阿里云、npm 走 npmmirror），那部分不用管。

### 不用 Docker 的话，要装三样

| 软件 | 版本 | 备注 |
|---|---|---|
| Python | **3.10 ~ 3.12** | 别用 3.13/3.14，太新，部分依赖没有预编译包会编译失败 |
| Node.js | 18 以上，建议 LTS 20 | 自带 npm |
| MySQL | 8.x | 也可以不装，`.env` 里配 SQLite，但多人用不推荐 |

磁盘：虚拟环境约 78MB + 前端依赖约 123MB + MySQL 约 500MB。

`git` 两条路线都是可选的，用来拉代码；直接拷贝文件夹也行。

## 三、部署步骤（Docker，推荐）

### 全新 Ubuntu 服务器：一条命令搞定

什么都没装的机器，直接跑这一条（会装 git、拉代码、装 Docker 配国内镜像、部署）：

```bash
curl -fsSL https://raw.githubusercontent.com/c200108/A_System_of_WFXXKJ_Simulating_Examination/main/scripts/bootstrap.sh | sudo bash
```

代码会放到 `/opt/A_System_of_WFXXKJ_Simulating_Examination`。中途会问你对外访问地址和端口。

GitHub 拉不动的话，先把仓库弄到机器上（ZIP 上传也行），进目录后执行：

```bash
sudo bash scripts/bootstrap.sh
```

下面是分步说明，想逐步来或排查问题时看。

### 0. 国内服务器先准备 Docker（Ubuntu / Debian）

国内机器直连 `get.docker.com` 和 Docker Hub 基本都不通，先跑这个：

```bash
sudo bash scripts/setup-docker-cn.sh
```

它做三件事：用阿里云 apt 源装 Docker、**逐个实测国内镜像加速站只写入真正能用的**、
拉个小镜像验证。默认首选 `https://docker.1ms.run`（2026-09 实测可用），
不通时自动往下试备选站。

公共加速站关停限流频繁，全都不通时申请阿里云专属加速器（免费，需账号，在
<https://cr.console.aliyun.com> 的「镜像工具 → 镜像加速器」）：

```bash
DOCKER_MIRROR=https://你的ID.mirror.aliyuncs.com sudo -E bash scripts/setup-docker-cn.sh
```

> 少数镜像站只能当**仓库前缀**用、当不了透明加速器。这种走的是 `.env` 里的
> `REGISTRY`，默认已经写成 `docker.1ms.run`，一般不用管。
>
> 要换成别的站，改 `.env` 里那一行即可（改完 `docker compose up -d --build`）：
>
> ```
> REGISTRY=docker.1ms.run
> ```
>
> 能直连 Docker Hub 的机器（比如海外服务器）把它改成 `docker.io`。

已经装好 Docker 且能正常拉镜像的机器（比如海外服务器），跳过这一步。

### 1. 拿到代码

```bash
git clone https://github.com/c200108/A_System_of_WFXXKJ_Simulating_Examination.git
cd A_System_of_WFXXKJ_Simulating_Examination
```

### 2. 一键部署

**Windows**：双击项目根目录的 `一键部署.bat`

**Linux / macOS**：

```bash
chmod +x deploy.sh && ./deploy.sh
```

它自动做完六件事：

1. 检查 Docker 装没装、跑没跑（没有就告诉你去哪下、要注意什么）
2. 生成 `.env`，口令全部本机随机生成；已有配置会先检查是不是还用着示例默认值
3. 检查端口占用
4. 构建并启动，**拉镜像失败自动重试 3 次**（国内网络常见）
5. 等后端健康检查通过（首次要建库、导题库，约 1 分钟）
6. 验证业务链路：接口健康 → 管理员登录 → 报出题库题数

跑完直接打印访问地址和管理员密码。**密码只显示这一次，请当场记下**（也在 `.env` 里）。

中途任何一步失败都会给出可操作的提示，比如拉镜像超时会告诉你怎么配国内加速。

### 4. 开放端口

- **云服务器**：在厂商控制台的「安全组 / 防火墙」里放行 **8080** 入站。这一步最容易漏，不放行的话页面打不开
- **Linux 本机防火墙**：`sudo ufw allow 8080/tcp`（Ubuntu）或 `firewall-cmd --add-port=8080/tcp --permanent && firewall-cmd --reload`（CentOS）
- **Windows**：控制面板 → 高级安全 Windows Defender 防火墙 → 入站规则 → 新建规则 → 端口 8080

### 5. 访问

浏览器打开 `http://你的公网IP:8080`，用 `.env` 里的管理员账号登录。

接口文档在 `http://你的公网IP:8080/docs`。

## 四、把老数据搬过去

> **还原过程中卡住了？** 看 [数据还原排障.md](数据还原排障.md) —— 卡在「还在等
> 数据库初始化」、认证不通过、`backend is unhealthy`、还原后端口变回 8080，

### 路线 A：搬旧机器的真实数据（推荐，什么都不丢）

**旧机器上导出：**

```bash
mysqldump -u root -p --single-transaction --default-character-set=utf8mb4 exam > exam.sql
```

然后把这两样拷到新机器（U 盘、scp 都行）：

- `exam.sql`
- `backend/data/uploads/` **整个目录**（题目配图在里面，不在数据库里）

**新机器上导入**（在项目目录下，容器已经起来）：

```bash
docker compose exec -T db mysql -u root -p"你在.env里设的MYSQL_ROOT_PASSWORD" --default-character-set=utf8mb4 exam < exam.sql
```

配图目录放到项目下的 `data/uploads/`，`docker-compose.yml` 已经把它挂进容器了。

导完重启后端让它重新连接：

```bash
docker compose restart backend
```

### 路线 B：只要原始 331 题

什么都不用做，首次启动已经自动导好了。
**但老师后来补充的题、历史试卷、考试成绩不会有**，那些只在旧机器的数据库里。

## 五、公网部署必须知道的三件事

### 1. HTTPS —— 可选，填两项配置就开

不配的话是 http，意味着**教师密码、学生答案在网络上是明文传输的**。同一个 WiFi 下有人抓包就能看到。
内网用可以先不管，对外提供服务、或者有自己的域名，建议开上。

前端容器自带 HTTPS 支持，**默认关着**：`.env` 里 `SSL_CERT_DIR`、`HTTPS_PORT` 都留空时
和以前完全一样只有 http，也不会占用宿主机的 443。两项都填上，容器启动时自动：

- 开 443，用证书目录里的 `fullchain.pem` 和 `key.pem`；
- http 上打开网页一律 301 跳到 https（跳到 `PUBLIC_BASE_URL`，它不是 https 就跳到同一主机名）；
- `/api/` 和 `/uploads/` 在 http 上**照常服务、不跳转** —— 学生端 exe 不跟随跳转，
  填着 http 地址的老 exe 照旧能用（只是仍是明文；想全程加密，把 exe 里的地址改成 https 的）；
- 每小时看一眼证书，续期换了文件就自动 `nginx -s reload`，不用重启。

证书配错（目录不对、证书和私钥不配套）时不会让整站起不来，而是先按 http 跑，
`docker compose logs frontend | grep exam-https` 能看到原因。

下面以「域名托管在 Cloudflare、用 acme.sh 申请 Let's Encrypt 通配符证书」为例，
其他 DNS 服务商把 `dns_cf` 换成对应的插件即可（见 acme.sh 文档的 dnsapi 列表）。
用 **DNS 验证**，所以服务器在内网、域名解析到内网 IP（比如 Cloudflare 上设成「仅 DNS」灰色云、
指向 10.x.x.x）也能申请 —— Let's Encrypt 不需要从外网连进来。

#### ① 在 Cloudflare 建 API 令牌

Cloudflare 后台 → 我的个人资料 → API 令牌 → 创建令牌 → 用「编辑区域 DNS」模板，
「区域资源」只选你的域名（如 `ru6.top`）。复制生成的令牌，**只显示一次**。

#### ② 在服务器上装 acme.sh 并申请证书（全程用 root）

```bash
sudo -i
curl https://get.acme.sh | sh -s email=你的邮箱@example.com
# 国内服务器连不上的话：git clone https://gitee.com/neilpang/acme.sh.git && cd acme.sh && ./acme.sh --install -m 你的邮箱
source ~/.bashrc

acme.sh --set-default-ca --server letsencrypt

export CF_Token="上一步的 API 令牌"
acme.sh --issue --dns dns_cf -d ru6.top -d '*.ru6.top'
```

令牌会被 acme.sh 记到 `~/.acme.sh/account.conf`，以后续期自动用，不用再 export。

#### ③ 把证书装到固定目录

```bash
mkdir -p /etc/ssl/ru6.top
acme.sh --install-cert -d ru6.top \
    --key-file       /etc/ssl/ru6.top/key.pem \
    --fullchain-file /etc/ssl/ru6.top/fullchain.pem \
    --reloadcmd      "cd /opt/A_System_of_WFXXKJ_Simulating_Examination && docker compose exec -T frontend nginx -s reload"
```

- 提示找不到证书的话加上 `--ecc`（acme.sh 默认申请的是 ECC 证书）。
- `--reloadcmd` 里的目录换成你实际的项目目录。它让续期后**立刻**生效；不写也行，
  容器自己每小时检查一次。第一次执行时前端容器还没开 HTTPS 的话它会报错，不用管。
- acme.sh 装好后自带每天一次的定时任务，证书大约每 60 天自动续期，并重新装到上面这两个文件。
  `crontab -l | grep acme` 能看到。

#### ④ 改 .env，重建前端

```bash
SSL_CERT_DIR=/etc/ssl/ru6.top
HTTPS_PORT=443
# 这两项也要改成 https 地址，否则老师复制出去的学生链接还是 http 的
PUBLIC_BASE_URL=https://exam.ru6.top
CORS_ORIGINS=https://exam.ru6.top
```

```bash
python3 backend/tools/check_deploy.py         # 会检查证书文件在不在、地址是不是 https
docker compose up -d --build                  # 前端镜像有改动，第一次要 --build
docker compose logs frontend | grep exam-https   # 应看到「HTTPS 已启用」
```

验证：

```bash
curl -I http://exam.ru6.top/          # 301，Location 是 https://exam.ru6.top/
curl -I https://exam.ru6.top/         # 200
acme.sh --list                        # 看证书到期时间
```

#### ⑤ 端口：从外面到容器的每一层都要放行 443

- 服务器防火墙：`sudo ufw allow 443/tcp`；云服务器还要在安全组放行 443。
- **Windows 主机上跑虚拟机（NAT）的**：主机要像 80 一样，把 443 也转到虚拟机的 443。
  - VMware：编辑 → 虚拟网络编辑器 → VMnet8（NAT）→ NAT 设置 → 端口转发，加一条
    主机 443 → 虚拟机 IP 的 443；VirtualBox 在虚拟机的「网络 → 端口转发」里加。
  - 用 netsh 转发的（管理员 PowerShell，虚拟机 IP 换成实际的）：

    ```powershell
    netsh interface portproxy add v4tov4 listenaddress=0.0.0.0 listenport=443 connectaddress=虚拟机IP connectport=443
    netsh advfirewall firewall add rule name="exam-https" dir=in action=allow protocol=TCP localport=443
    ```
  - 主机上的 IIS 等如果占着 443，要先停掉或解除绑定。
  - WSL2 部署的：`scripts\win-server-port-forward.ps1 -Port 443` 再跑一次。
- 外部端口不是 443 的（比如只能用 8443）：`HTTPS_PORT=8443`，`PUBLIC_BASE_URL` 也写成
  `https://域名:8443`，跳转就会带上端口。

#### 说明

- 证书只认域名。用 IP（`https://10.9.22.125`）打开会报证书不安全，学生、老师都用域名访问。
- 没有加 HSTS：开了之后浏览器会强制只走 https，以后想退回 http 很麻烦，确认长期用 https 再自己加。
- 想关掉 HTTPS：把 `HTTPS_PORT` 清空，`docker compose up -d`。
- 不用 Docker、自己装 nginx 的，可以照 `frontend/nginx/https.conf` 写。

### 2. 备案 —— 国内服务器绕不开

在中国大陆的服务器上对外提供网页服务需要 **ICP 备案**。很多云厂商对未备案的机器直接封禁 80/443 端口。

用 8080 这类非标准端口通常不会被封，但这是灰色地带，学校正式使用建议走备案流程，或者部署在**校园内网**。

### 3. 登录接口没有防爆破

系统没有做登录失败次数限制。公网暴露时，靠的是「管理员密码足够强」这一条防线。所以第一节里那个 12 位以上强口令不是客套话。

如果要加固，可以在前面挂一层 Nginx 做限流。

## 六、日常维护

### 备份（重要）

`backup/backup.sh` 每天备份数据库和上传目录，保留 30 天。加进 crontab：

```bash
0 2 * * * /opt/A_System_of_WFXXKJ_Simulating_Examination/backup/backup.sh
```

路径按实际存放位置改。**部署当天就把备份设好**，别等出事才想起来。

### 网页上备份和升级（2.18.0 起，推荐）

**系统管理员**（部署时 `.env` 里 `ADMIN_USERNAME` 的那个账号，别的管理员看不到）登录后台 →
右上角「我的账号」→「数据备份与系统更新」：

| 按钮 | 做什么 | 网站会不会断 |
|---|---|---|
| 导出数据 | 下载 `exam-data-时间.zip`：全部数据表、配图、config.yaml，不含口令。解压出来的 `exam-data` 和 `data-export.sh` 导的一模一样 | 不断 |
| 导入并重建容器 | 上传 exam-data 压缩包 → 先体检、试算（不对当场报，什么都不动）→ 存回滚点 → 覆盖数据 → 重建后端、前端容器 | 重建时断一会儿 |
| 一键更新（途径一） | 服务器从 GitHub 下载 main 压缩包，照下面「用 ZIP 升级」的三步自动升级 | 切换时断十几秒 |
| 上传并更新（途径二） | 服务器连不上 GitHub 时，自己下载 main 压缩包传上来，其余同上 | 切换时断十几秒 |

导入、升级都要再输一次登录密码。压缩包文件名随意（`xxx-main (1).zip` 也行），服务器按实际文件名执行。

**前提：服务器上装了「主机助手」。** 重建容器、跑升级脚本只能在宿主机上做，容器里的网页后端够不着
（也不该够得着），所以网页只负责收文件、体检，然后给主机助手留单子：

```bash
sudo bash scripts/host-agent-install.sh      # 装一次；deploy.sh、update-from-zip.sh 跑完会自动装
sudo bash scripts/host-agent-install.sh --remove   # 不想要了就卸掉
```

装的是 systemd 的 `exam-host-agent.path`（盯着 `data/host-jobs/queue/`）和 `exam-host-agent.service`
（跑 `scripts/host-agent.sh`，干完就退出，不常驻）。它只认「导入」「GitHub 更新」「压缩包更新」三种动作。
执行日志在网页上实时显示，也留在 `data/host-jobs/jobs/<任务号>/log.txt`。

老服务器第一次：先用下面任意一种命令行方式升级到 2.18.0，升级脚本跑完主机助手就装好了，以后都能在网页上点。

### 升级（命令行）

服务器能连 GitHub：

```bash
git pull && docker compose up -d --build
```

数据库在 Docker 卷里、上传目录挂在宿主机，容器重建都不丢。

#### 用 GitHub 下载的 ZIP 升级（服务器连不上 GitHub 时）

仓库页 Code → Download ZIP，把 `A_System_of_WFXXKJ_Simulating_Examination-main.zip` 传到服务器
（比如放在 `~/`），**不用解压**。先从 ZIP 里取出新版的升级脚本（服务器上那份可能是旧的），再运行：

```bash
unzip -p ~/A_System_of_WFXXKJ_Simulating_Examination-main.zip '*/scripts/update-from-zip.sh' > /tmp/update.sh
sudo bash /tmp/update.sh ~/A_System_of_WFXXKJ_Simulating_Examination-main.zip
```

它做的事（`scripts/update-from-zip.sh` 开头有详细说明）：

1. 先备份到 `/opt/exam-backups/`：`.env`、`config.yaml`、`data/uploads`、旧代码，数据库在线导出（不停库）；
2. **原地覆盖**代码，`.env`、`data/`、`config.yaml`、备份文件原地不动；
3. 旧容器照常服务的同时构建新镜像 —— **构建失败就自动把代码还原**，线上不受影响；
4. 构建好了只换后端、前端容器，**数据库容器不重启**；新后端启动时自动升级数据库结构；
5. 新版本多出来的配置项合进 `config.yaml`（你改过的值全留着），最后核对题目数、答卷数、打字成绩数。

部署目录自动找（正在跑的容器上记着），镜像源沿用 `.env` 里的 `REGISTRY`（如 `docker.1ms.run`）。
切换那一下网页会有十几秒打不开，**避开考试时段**。

> **不要删掉项目目录重新部署。**
>
> 数据库的数据卷不在项目目录里（它叫 `exam-system_db_data`，归 Docker 管），
> 删项目目录它不会跟着删 —— 但 `.env` 会。而数据库的口令是**存在库里的**，
> MySQL 只在第一次初始化时采用 `MYSQL_PASSWORD`，之后再也不看这个变量。
>
> 于是重新部署时 `deploy.sh` 生成一份新的随机口令，旧库还认着旧口令，后端怎么
> 都连不上，报出来的却是这么一句，一点都看不出是口令的事：
>
> ```
> dependency failed to start: container exam-system-backend-1 is unhealthy
> ```
>
> 2.4.1 起 `deploy.sh` 会在这种情况下停下来并给出三条路，不会再生成一份注定连不
> 上的配置。万一旧 `.env` 真找不回来了，用这个脚本把库里的口令改成新的（会先自
> 动导出一份 SQL 备份）：
>
> ```bash
> bash scripts/reset-db-password.sh
> ```
>
> 想彻底避开这件事：**先备份 `.env`**。`scripts/data-export.sh` 导出的那份
> `env.secrets` 里就有，或者简单点 `cp .env /opt/exam-backups/env-$(date +%F)`。

### 改配置

- 改**业务配置**（默认题量、及格线、卷头等）：改 `config.yaml` → `docker compose restart backend`，不用重新构建
- 改**密码/端口**：改 `.env` → `docker compose up -d`

### 常用命令

```bash
docker compose ps               # 看状态
docker compose logs -f backend  # 看后端日志
docker compose restart backend  # 重启后端
docker compose down             # 停止（数据不丢）
```

## 九、Windows Server 2022 上部署

**先说清楚**：Docker Desktop 官方不支持 Windows Server。所以走
「WSL2 里装 Ubuntu，在 Ubuntu 里跑 Docker」这条路——脚本和 Linux 完全一样。

### 1. 装 WSL2 和 Ubuntu

管理员 PowerShell：

```powershell
wsl --install -d Ubuntu-22.04
```

**装完必须重启服务器。** 重启后会自动进入 Ubuntu 设置，创建一个用户名和密码。

### 2. 让 WSL 支持开机自启服务

在 Ubuntu 里：

```bash
sudo tee /etc/wsl.conf > /dev/null <<'CONF'
[boot]
systemd=true
CONF
```

回到 PowerShell 执行 `wsl --shutdown`，再重新 `wsl` 进入。没有这一步 Docker 不会开机自启。

### 3. 部署（在 Ubuntu 里）

```bash
curl -fsSL https://raw.githubusercontent.com/c200108/A_System_of_WFXXKJ_Simulating_Examination/main/scripts/bootstrap.sh | sudo bash
```

装 Docker、配国内镜像、部署，全自动。中途问你访问地址和端口。

### 4. 打通外网访问（**这一步不能省**）

WSL2 是 NAT 网络。做完第 3 步，你在服务器上访问 `localhost:8080` 是通的，
但**外网访问公网 IP 打不开**——学生进不来。

回到 Windows，管理员 PowerShell，在项目目录里：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\win-server-port-forward.ps1
```

它做三件事：把 `0.0.0.0:8080` 转发到 WSL 内网 IP、放行 Windows 防火墙、
**注册开机任务**（WSL 的 IP 每次重启都变，必须自动重设）。

> 项目代码在 WSL 里，Windows 侧取这个脚本最简单的办法：
> `copy \wsl$\Ubuntu-22.04\opt\A_System_of_WFXXKJ_Simulating_Examination\scripts\win-server-port-forward.ps1 .`

### 5. 云服务器安全组

在厂商控制台放行 **8080** 入站。这一步最容易漏。

然后用 `http://公网IP:8080` 访问。

### 日常操作

都在 WSL 的 Ubuntu 里，和 Linux 完全一样：

```bash
cd /opt/A_System_of_WFXXKJ_Simulating_Examination
docker compose ps                # 看状态
docker compose logs -f backend   # 看日志
git pull && docker compose up -d --build   # 升级
```

### 外网突然打不开时

八成是 WSL 重启换了 IP 而开机任务没跑成。管理员 PowerShell 重跑一次：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\win-server-port-forward.ps1
```

## 十一、换服务器：整库搬家

从旧服务器搬到新服务器，或者做一次可带走的完整备份，用这两个脚本。

### 在旧服务器上导出

```bash
cd /opt/exam-system && sudo bash scripts/data-export.sh
```

导出到 `./exam-data/`，里面五个文件：

| 文件 | 内容 |
|---|---|
| `database.sql.gz` | 整个 MySQL 库：题库、教师账号、学生账号、成绩、反馈、更新日志 |
| `uploads.tar.gz` | 题目配图、导入的 Excel 原件 |
| `config.yaml` | 平台配置 |
| `env.secrets` | **明文口令**，权限 600 |
| `MANIFEST.txt` | 导出时间、迁移版本、各表行数 —— 还原后拿它核对 |

想导到 U 盘就加个路径：`sudo bash scripts/data-export.sh /mnt/usb`。

⚠️ `env.secrets` 里是明文数据库口令和管理员初始口令。整个文件夹**不要**进版本库、
不要发微信群，拷完确认新服务器正常后建议删掉中转副本。

### 在新服务器上还原

前提：新机器已装好 docker（没装先跑 `scripts/setup-docker-cn.sh`），项目代码已解压到位。

```bash
# 把 exam-data 整个文件夹拷过来，然后：
cd /opt/exam-system && sudo bash scripts/data-import.sh ~/exam-data
```

脚本会要求你**手工输入「还原」两个字**才动手，然后：

1. 用导出的口令生成 `.env` —— 口令必须一致，否则连不上还原出来的库；
2. 起数据库容器，等它真的能应答（最多等 2 分钟）；
3. 灌 SQL、还原配图和配置；
4. 起全部服务，后端启动时自动跑 `alembic upgrade head`，旧版本的库会被升到当前版本；
5. **按 MANIFEST 逐表核对行数**，对不上会报红。

最后一步很重要：一张表都没核对成功时脚本会明确报红，不会假装成功。
看到「核对的 N 张表行数全部对得上」才算真的搬完。

### 搬完检查

- 访问 `http://新服务器IP:端口/` 应该是**学生平台**登录页
- 访问 `http://新服务器IP:端口/js` 应该是**教师后台**
- 用原来的账号密码登录，题目数和学生数和 MANIFEST 对得上
