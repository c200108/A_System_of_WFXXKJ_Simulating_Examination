# 部署到有公网 IP 的机器

面向的场景：把项目搬到一台能被外网访问的电脑/服务器上，让全校师生用。

> 只是换台自己电脑单机用？不用看这篇，直接 `git clone` 后双击 `一键启动.bat`（Linux/macOS 用 `./start.sh`）。

---

## 一、先回答：能直接用吗

**不能。** 代码不用改一行，但有 **3 个默认值必须改**，否则等于门户大开。

| 项 | 默认值 | 不改的后果 |
|---|---|---|
| `JWT_SECRET` | `change_this_...` | 这串值公开在 GitHub 上，**任何人都能伪造管理员令牌**直接登入 |
| `ADMIN_PASSWORD` | `admin123` | 公网扫描器几分钟内爆破，对方能看到全部题目和答案 |
| `MYSQL_PASSWORD` | `exam_pwd` | 数据库口令公开 |

项目里带了自检脚本，改完跑一遍确认：

```bash
python backend/tools/check_deploy.py
```

它会把没改的默认值全部揪出来，并顺便生成一串安全的随机密钥。退出码 0 才可以部署。

### 架构上已经准备好的部分

这些不用你操心：

- 前端请求走相对路径 `/api`，**换任何 IP 或域名都不用改代码、不用重新构建**
- 学生答题链接用 `location.origin` 拼，自动跟着实际访问地址走
- MySQL 只在 Docker 内网，**没有暴露到宿主机**，外网连不到数据库
- 对外只开一个端口（默认 8080）

## 二、部署步骤（Docker，推荐）

新机器需要：Docker + Docker Compose。Windows 装 Docker Desktop，Linux 装 docker-ce。

### 1. 拿到代码

```bash
git clone https://github.com/c200108/A_System_of_WFXXKJ_Simulating_Examination.git
cd A_System_of_WFXXKJ_Simulating_Examination
```

### 2. 写配置

```bash
cp .env.example .env
```

编辑 `.env`，**至少改这四项**：

```
MYSQL_ROOT_PASSWORD=换成你的强口令
MYSQL_PASSWORD=换成另一个强口令
JWT_SECRET=换成 32 位以上随机串
ADMIN_PASSWORD=换成 12 位以上强口令
```

需要随机密钥就跑一下自检脚本，它会生成一串给你：

```bash
python backend/tools/check_deploy.py
```

反复跑到显示「检查通过」为止。

### 3. 起服务

```bash
docker compose up -d --build
```

首次构建要几分钟。完成后看状态：

```bash
docker compose ps
```

三个容器（db / backend / frontend）都是 running 就正常。有问题看日志：

```bash
docker compose logs -f backend
```

### 4. 开放端口

- **云服务器**：在厂商控制台的「安全组 / 防火墙」里放行 **8080** 入站。这一步最容易漏，不放行的话页面打不开
- **Linux 本机防火墙**：`sudo ufw allow 8080/tcp`（Ubuntu）或 `firewall-cmd --add-port=8080/tcp --permanent && firewall-cmd --reload`（CentOS）
- **Windows**：控制面板 → 高级安全 Windows Defender 防火墙 → 入站规则 → 新建规则 → 端口 8080

### 5. 访问

浏览器打开 `http://你的公网IP:8080`，用 `.env` 里的管理员账号登录。

接口文档在 `http://你的公网IP:8080/docs`。

## 三、把老数据搬过去

⚠️ **Docker 部署起来后题库是空的**。容器启动只做「建表 + 建管理员 + 灌字典」，不会自动导题。

两条路，选一条。

### 路线 A：搬旧机器的真实数据（推荐，什么都不丢）

**旧机器上导出：**

```bash
mysqldump -u root -p --single-transaction --default-character-set=utf8mb4 exam > exam.sql
```

然后把这两样拷到新机器（U 盘、scp 都行）：

- `exam.sql`
- `backend/data/uploads/` **整个目录**（题目配图在里面，不在数据库里）

**新机器上导入**（在项目目录下，容器已经起来）：

```bash
docker compose exec -T db mysql -u root -p"你在.env里设的MYSQL_ROOT_PASSWORD" --default-character-set=utf8mb4 exam < exam.sql
```

配图目录放到项目下的 `data/uploads/`，`docker-compose.yml` 已经把它挂进容器了。

导完重启后端让它重新连接：

```bash
docker compose restart backend
```

### 路线 B：从零开始，只要原始 331 题

仓库里带着 `legacy/信息技术组卷台.html`，可以直接从它重建：

```bash
docker compose exec backend python -m tools.migrate_from_html
```

会导入 331 题和 26 张配图。**老师后来补充的题、考试成绩不会有**。

## 四、公网部署必须知道的三件事

### 1. HTTPS —— 现在没有

当前是 http，意味着**教师密码、学生答案在网络上是明文传输的**。同一个 WiFi 下有人抓包就能看到。

内网用可以先不管，对外提供服务建议加上。最省事的做法是用 Caddy 自动申请证书（需要域名）：

```
你的域名 {
    reverse_proxy localhost:8080
}
```

或者用 Nginx + Let's Encrypt。

### 2. 备案 —— 国内服务器绕不开

在中国大陆的服务器上对外提供网页服务需要 **ICP 备案**。很多云厂商对未备案的机器直接封禁 80/443 端口。

用 8080 这类非标准端口通常不会被封，但这是灰色地带，学校正式使用建议走备案流程，或者部署在**校园内网**。

### 3. 登录接口没有防爆破

系统没有做登录失败次数限制。公网暴露时，靠的是「管理员密码足够强」这一条防线。所以第一节里那个 12 位以上强口令不是客套话。

如果要加固，可以在前面挂一层 Nginx 做限流。

## 五、日常维护

### 备份（重要）

`backup/backup.sh` 每天备份数据库和上传目录，保留 30 天。加进 crontab：

```bash
0 2 * * * /opt/A_System_of_WFXXKJ_Simulating_Examination/backup/backup.sh
```

路径按实际存放位置改。**部署当天就把备份设好**，别等出事才想起来。

### 升级

```bash
git pull && docker compose up -d --build
```

数据库在 Docker 卷里、上传目录挂在宿主机，容器重建都不丢。

### 改配置

- 改**业务配置**（默认题量、及格线、卷头等）：改 `config.yaml` → `docker compose restart backend`，不用重新构建
- 改**密码/端口**：改 `.env` → `docker compose up -d`

### 常用命令

```bash
docker compose ps               # 看状态
docker compose logs -f backend  # 看后端日志
docker compose restart backend  # 重启后端
docker compose down             # 停止（数据不丢）
```

## 六、不用 Docker 的话

新机器上装 Python 3.10+、Node.js 18+、MySQL 8，然后：

1. `git clone` 代码
2. `cp backend/.env.example backend/.env`，把 `DATABASE_URL` 改成本机 MySQL 地址
3. 跑一遍 `python backend/tools/check_deploy.py backend/.env`
4. Windows 双击 `一键启动.bat`，Linux/macOS 执行 `./start.sh`

但这种方式跑的是开发服务器（uvicorn + vite），**不适合长期对外服务**：没有进程守护、重启不会自动拉起、性能也差一截。对外用还是走 Docker。
