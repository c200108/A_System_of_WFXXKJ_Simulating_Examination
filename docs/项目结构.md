# 项目结构说明

逐个文件讲清楚"这是干什么的"，翻代码时对照着看。

- 想知道**怎么跑起来、怎么部署** → 看 [../README.md](../README.md)
- 想知道**某个文件是干嘛的、该改哪里** → 看本文

---

## 一、先理解分层：谁依赖谁

```
前端 Vue ──HTTP──> routers/    接口层：URL、权限、状态码
                      ↓ 调用
                   services/   业务层：抽题、判分、解析、导出
                      ↓ 读写
                   models.py   数据层：表结构
                      ↓
                   database.py → SQLite / MySQL
```

改东西时的定位方法：

| 要改什么 | 去哪 |
|---|---|
| 接口地址、参数、权限 | `app/routers/` |
| 算法、业务规则 | `app/services/` |
| 数据库字段 | `app/models.py` + 新建 alembic 迁移 |
| 学校名、默认题量、及格线、导入规则 | `config.yaml`（不用改代码） |
| 页面长相、交互 | `frontend/src/views/` |

三层不要互相越级：路由里不写算法，服务里不碰 HTTP。

## 二、顶层文件

| 文件 | 作用 |
|---|---|
| `README.md` | 项目总说明书。怎么跑、表结构、接口清单、维护方法、已知待办 |
| `一键启动.bat` | **给老师用的**。检查环境 → 装依赖 → 建库 → 导题 → 起前后端 → 开浏览器，六步全自动。第一次约 3~5 分钟，之后十几秒 |

| `.env.example` | 部署配置模板（数据库密码、JWT 密钥、管理员密码、端口）。复制成 `.env` 再改 |
| `.gitignore` | 排除 `.venv`、`node_modules`、`data/`、`.env` 等不进版本库的东西 |

## 三、backend/ —— Python 后端

### 3.1 骨架层

每个文件只管一件事，出问题时能快速定位。

| 文件 | 行数 | 作用 |
|---|---|---|
| `app/main.py` | 40 | **入口**。创建 FastAPI 应用、挂 CORS、挂 `/uploads` 静态目录、注册 13 个路由 |
| `app/config.py` | 41 | **密钥与环境**相关配置，从环境变量读。改端口/密钥只动 `.env` |
| `app/siteconfig.py` | 147 | **读 `config.yaml`** 并严格校验。键名拼错、类型不对一律启动即报错并指出是哪一项，不静默失效 |
| `app/database.py` | 30 | 数据库连接与会话。SQLite 和 MySQL 都走这里，切换只改 `DATABASE_URL` |
| `app/models.py` | 300 | **15 张表的定义**，见 3.4 |
| `app/schemas.py` | 289 | 接口的出入参格式。`TakeQuestionOut` 故意不含 `answer` 字段 —— 答案不泄漏的第一道防线 |
| `app/security.py` | 32 | bcrypt 密码哈希 + JWT 令牌签发/校验 |
| `app/deps.py` | 52 | 登录校验 `get_current_user`、管理员校验 `require_admin`、可选登录 `get_optional_user`（公开接口想认出访客是谁时用），接口上挂一行就生效 |
| `app/constants.py` | 17 | 字典分类名等真常量；知识范围、题型等只是从 `config.yaml` 转出来的别名 |
| `app/seed.py` | 78 | 首次启动建管理员账号、灌字典表、灌打字文本与更新日志。可重复执行不出错 |
| `app/changelog_seed.py` | 120 | **更新日志的初始内容**。以后每次迭代把新版本追加到 `VERSIONS` 最前面 |

> ⚠️ 知识范围和题型有三个层次：`config.yaml` 是**建库种子** → `dict_items` 表是**运行期真相** →
> `constants.py` 只是把种子值转出来的别名。想加一类知识范围，改数据库（走界面），不要改代码。

### 3.2 services/ —— 五个核心算法（最值得看的部分）

这几个文件的规则参数（题型关键词、答案写法、分隔符、卷号前缀等）都读 `config.yaml`，不写死。

| 文件 | 行数 | 内容 |
|---|---|---|
| `app/services/sampler.py` | 69 | **均衡抽题**。名额在十个知识范围之间轮流分配，某范围题不够时名额自动让给别人。从原 HTML 的 `allocate`/`pick` 原样移植 |
| `app/services/paper.py` | 137 | **组卷排版**。调 sampler 抽题 → 打乱选择题选项（答案自动跟随）→ 按题型分大题 → 生成卷号 |
| `app/services/importer.py` | 244 | **Excel/CSV 解析与逐行校验**。题型识别、判断题答案归一（√/×/对/错/T/F）、选项拆分、题干哈希查重。从原 `handleRows` 移植 |
| `app/services/exam.py` | 164 | **考试取卷与判分**。`strip_answers()` 去答案发给学生，`grade()` 在服务端判分 |
| `app/services/export.py` | 225 | 三种导出：题库 Excel、本卷 Excel、学生答题网页（图片转 data URI 内嵌，可独立分发） |

> 🔒 **删除公共资源要 `require_delete_permission`。** 题库、练习文本、更新日志、
> 打字成绩是全校共用的，普通教师默认删不动，管理员在「账号」页面开 `can_delete`。
> 加新的删除接口时想一下：这东西是全校共用的吗？是就挂这个依赖。

> 🔒 **教师和学生是两套身份，两张表，两种令牌。** `students.py` 里 `/api/student/*`
> 认学生令牌、`/api/students/*` 认教师令牌；令牌里带 `typ` 标记（见 `security.py`），
> 学生令牌调不通任何教师接口。加新接口时想清楚该用 `get_current_user` 还是
> `get_current_student`，别图省事共用一个。

> ⚠️ 文件名是 `typing_train.py` 不是 `typing.py` —— 叫 `typing.py` 会盖掉标准库的 `typing`，一启动就崩。

> 🔒 **答案只在 `exam.py` 的 `grade()` 里被读到。** 改这个文件要格外小心，改完必跑测试。

### 3.4 数据库表（`models.py` 里的 15 张）

| 表 | 存什么 |
|---|---|
| `users` | 账号、bcrypt 哈希、姓名、角色（admin/teacher）、任教年级班级、联系方式、是否停用 |
| `dict_items` | 知识范围、题型两类枚举 —— 加一类只改数据不改代码 |
| `questions` | 题型、题干、答案、知识范围、来源、图片路径、必出标记、**软删除标记**、题干哈希 |
| `options` | A/B/C/D 选项，随题目级联删除 |
| `papers` | 存档试卷的抬头：标题、学校、时长、卷号 |
| `paper_items` | 试卷的题目顺序 + **打乱后的选项快照**（重开历史卷和当初印的一模一样） |
| `exams` | 发布的考试：口令、开放状态、四个开关、**发布人**（老师之间靠它隔离） |
| `exam_submissions` | 学生答卷：原始作答、判分明细、得分。平台上交的关联学生账号，凭链接匿名交的不关联 |
| `import_logs` | 谁、何时、导了什么文件、成功失败几条、原件存哪 |
| `typing_records` | 打字练习成绩：模块、速度、正确率、用时，学生免登录上报 |
| `typing_texts` | 打字练习文本库：中英文 × 三档难度，内容哈希去重 |
| `feedbacks` | 需求反馈：称呼、联系方式、分类、内容、是否公开 |
| `feedback_replies` | 反馈下的回复，一位老师一条，署名冗余存一份 |
| `feedback_likes` | 点赞，(反馈, 老师) 唯一，再点一次就是取消 |
| `changelog_entries` | 更新日志：版本号、发布日期、变动类型、内容 |

两个刻意的设计：

- **题目软删除**（`is_deleted` 标记）而非物理删除，误删能恢复
- **图片存文件不存 base64**，数据库里只记路径，不会被撑爆
- **反馈的联系方式不进公开接口**：`FeedbackOut` 里根本没有 `contact` 字段，只有管理员专用的 `/api/feedback/all` 才带
- **考试按发布人隔离**：老师看不到别人的考试，直接拿 id 打接口也回 404（连「这个 id 存在」都不告诉），管理员不受限

**以后改表结构一律新增迁移文件，不手工改表：**

```bash
cd backend
alembic revision --autogenerate -m "给题目加难度字段"
alembic upgrade head
```

容器启动会自动执行 `alembic upgrade head`，服务器上不用手动跑。

## 六、三条维护要点

1. **加新知识范围** → 调 `POST /api/dicts`（或直接改 `dict_items` 表），前端下拉框和导入校验立刻生效，不用改代码、不用重新部署
2. **改表结构** → 写 alembic 迁移，不手工改表
3. **改考试相关代码** → 跑 `pytest`，特别确认 `test_answers_never_reach_the_student` 还过

## 七、两条容易踩的坑

- **`config.yaml` 里的 `bank.scopes` 不是运行期的知识范围清单**。它只在第一次建库时灌种子，之后系统以数据库 `dict_items` 表为准，日常增删走界面。想让文件说了算，把 `bank.sync_on_start` 改成 `true`。
- **新加可配置项要走三步**：在 `config.yaml` 加字段 → 在 `siteconfig.py` 的对应模型里声明（否则 `extra="forbid"` 会报错）→ 用到的地方读 `site.xxx`。前端要用的，还得在 `routers/config.py` 里放行。
- **学生端接口不要图省事复用教师端的 schema**。`TakeQuestionOut` 之所以单独定义且不含 `answer`，就是为了让"发答案给学生"这件事在类型层面做不到。复用 `QuestionOut` 会直接泄漏答案。
