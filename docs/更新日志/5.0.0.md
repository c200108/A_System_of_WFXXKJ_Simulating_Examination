# 教师端 APP 5.0.0 —— 教师端安卓 APP；教师端网页手机适配

发布：2026-10-08

新开一条产品线：**5.x = 教师端安卓 APP**（2.x 平台网页、3.x 仿真环境、4.x 学生桌面端）。

## 这次解决了什么

老师想在手机上发考试、看成绩、批操作题，以前只能用手机浏览器开电脑版网页：顶栏菜单挤出屏幕、
表格要左右拖、对话框比屏幕还宽，导出的 Excel 在手机浏览器里经常下不下来；令牌 12 小时过期，
早上登一次下午再开就被踢回登录页。

## 怎么做的

### 选型：原生外壳 + 服务器上的教师端网页

APP 的登录页是原生的（填服务器地址、账号、密码），登进去之后用 WebView 打开服务器上这套教师端网页。

没选「用原生界面把教师端重写一遍」：教师端二十来个页面、一万多行，有仿真操作题编辑器、
ECharts 成绩分析、Excel 导入这些重功能，重写一遍是两套界面，网页每加一个功能 APP 就得跟着
再写一遍再发一次版，迟早对不上 —— 而需求是「网页有的 APP 都有」。外壳方案下功能天然一致，
网页加了功能 APP 不用更新。

也没选「把前端打包进 APK」（Capacitor 那类）：那样前端版本跟着 APK 走，服务器升级了老师手机上
还是旧页面，接口一改就对不上；安装包也要好几 MB。现在 APK 不到 100 KB（只用系统自带组件，
不引任何第三方库：没有 AppCompat、没有 OkHttp），页面资源由 WebView 缓存，带指纹的文件
（nginx 已配一年缓存）第二次打开不再下载。

### 通讯：前台心跳续期，不用长连接

- **为什么不用 WebSocket**：系统里没有需要服务器主动推给老师的东西。长连接会让手机一直醒着、
  耗电，服务器要多维持一堆连接，nginx 还得另配升级头。
- **心跳**：`POST /api/app/session`，APP 在前台时每 5 分钟一次（间隔由服务器下发，
  `heartbeat_seconds`，以后想调不用重新发 APP）。退到后台立刻停，回到前台马上补一次。
  一次一两百字节。
- **续期**：令牌用掉四分之一寿命（12 小时的令牌即 3 小时）心跳就换一张新的，只要隔三差五打开过
  APP，令牌永远不会过期。新令牌通过 `window.__wfxxSetToken` 塞进页面，页面不刷新、正在填的表单不丢。
- **过期兜底**：手机放了好几天没开、令牌真过期了，用保存的账号密码在后台重新登录。密码只在勾了
  「记住密码」时保存，用 Android Keystore 的 AES-GCM 密钥加密（密钥导不出、卸载即删）。
  页面上任何接口回 401 也会触发这一步，登上后自动刷新当前页。只有密码被改、账号被停用才回登录页。
  在 APP 里改自己的密码，存着的那份跟着换。
- **断网**：心跳失败按 5/10/20/40/60 秒退避重试，系统报告网络恢复时立即重试；断开期间页面顶部
  一条黄色提示，恢复后收起。打开页面本身失败时显示「连不上服务器」页，网络恢复自动重载。
- **认服务器**：`GET /api/app/info`（公开），返回 `app: "wfxxkj-exam"`、协议版本、平台名称。
  登录前先调它，地址填错（少端口、填成别的网站）能当场说清楚，而不是登录时报「请求失败」。
  5.0 以前的服务器没有这两个接口：APP 退回去读 `/api/config` 认服务器、用 `/api/auth/me` 当心跳，
  能登录能用，只是没有自动续期，页面也还是电脑布局 —— **服务器要先升到这一版**。

### 网页和外壳之间的桥

外壳注入 `window.WfxxApp`（Java 的 `@JavascriptInterface`），网页侧集中在 `frontend/src/appBridge.js`，
不在 APP 里时全部不生效，浏览器里行为和以前完全一样。

| 网页里的事 | WebView 的问题 | 交给外壳 |
|---|---|---|
| 登录状态 | 外壳登录拿到的令牌页面不知道 | 启动时 `getToken/getUser` 同步进 localStorage |
| 导出 Excel、考试包 | WebView 不认 blob 链接的 `<a download>` | 分块（每块 384KB）base64 交给外壳，存进「下载/教学平台」（MediaStore，不用存储权限） |
| 复制考试链接 | http 页面里没有 `navigator.clipboard` | `copyText` |
| 打印、存 PDF | WebView 里 `window.print()` 什么都不做 | 系统打印服务 |
| 退出登录、401 | 会跳网页登录页 | 回原生登录页 / 后台重新登录 |
| 深浅色 | 状态栏和手势条颜色对不上 | `setDarkMode` 跟着换 |

令牌只交给本服务器的页面：外壳记着当前页面的主机，不是登录的那台服务器就返回空串。
外链（更新日志里的参考网址）交给系统浏览器打开。

### 教师端网页的手机布局

窄屏（≤768px，手机浏览器和 APP 都算）时：

- 顶栏菜单换成「标题栏 + 底部标签栏」：组卷、题库、考试、学生、我的。反馈、更新日志、账号管理、
  深色模式、退出登录收进新的「我的」页（`/js/me`，电脑上访问会转到「我的账号」）。
- 列表表格排成卡片：`v-mtable` 指令把表头文字抄到每个单元格的 `data-label` 上，
  `styles/mobile.css` 在窄屏时把每行排成「列名：内容」的卡片，「操作」列排在卡片底部，
  勾选框在右上角，表头只留「全选」。**列还是那些列，电脑上一个像素不变**，以后加列不用改两处。
  成绩分析里的统计表这类数字矩阵不加，保留表格左右滑。
- 对话框铺满全屏，标题和底部按钮吸顶吸底；表单标题移到输入框上方；筛选条一行两个。

## 踩到的坑

- **el-table 的 class 是绑定出来的**：直接 `classList.add('m-stack')`，学生列表一加载（滚动条出现、
  `max-height` 生效）Vue 重绘根元素的 class，整串覆盖，卡片排法就没了。改成 MutationObserver 连
  class 属性一起盯，被冲掉就补回来；为了不自己触发自己，每处改 DOM 前都先比对，值相同不碰。
- **「客观 / 操作」被当成了操作列**：一开始按「列名以『操作』结尾」判断操作列，成绩表的
  「客观 / 操作」分数列被排到了卡片底部。改成列名正好是「操作」，或没列名但里面全是按钮。
- **选文件**：`FileChooserParams.createIntent()` 会把网页写的 `accept=".xlsx,.csv"` 原样当 MIME
  类型，很多手机直接弹「没有应用可以执行此操作」。外壳自己把扩展名换成 MIME。
- **安卓 15 强制全面屏**：targetSdk 35 以后内容默认铺到状态栏下面。外壳在安卓 10~14 上也开成全面屏，
  统一按系统留白往里收，底部留白取导航栏和键盘中高的那个，各版本表现一致。

## 验证

- 后端 `tests/test_app_mobile.py`：info 公开且能认出本系统；心跳要教师令牌、学生令牌进不来；
  新令牌不换、用掉四分之一寿命的换新且新令牌能用；过期令牌不能续。
- 网页侧用 Playwright 模拟外壳（注入假的 `window.WfxxApp`）跑了 15 项：只凭外壳令牌进得去；
  导出题库 Excel 交给外壳、拼回来是完整 xlsx；2.5MB 文件分 7 块传完一字节不差；复制、打印、
  深浅色、退出登录都交给外壳；接口 401 时通知外壳而不跳网页登录页；外壳续期的新令牌写进页面。
- 390px 宽逐页截图检查：组卷、题库、导入、仿真、考试、成绩、打字学情、练习文本、学生、班级、
  反馈、我的账号、账号管理、更新日志、成绩分析，页面都不再横向溢出；1440px 宽电脑界面对照不变。
- 安卓工程用 javac + dx + aapt 打出了 APK（55 KB）并签名校验通过。**没有在真机或模拟器上跑过**
  （构建环境没有安卓模拟器），装机验证见 `android/README.md` 的检查清单。

## 升级注意

- **服务器先升级到这一版**（后端 + 前端都要重新部署），APP 才有手机布局和导出、复制、续期这些功能。
- APP 怎么打包、怎么签名、怎么发给老师，见 [android/README.md](../../android/README.md)。
