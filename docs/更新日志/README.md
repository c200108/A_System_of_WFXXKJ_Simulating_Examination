# 更新日志（详细版）

网页上的「更新日志」是给学校看的：一条一句话，说清改了什么、对使用者意味着
什么。**这里是给维护者看的**：每次发版一个文件，写清楚为什么这么改、当时是
怎么发现问题的、哪些坑不要再踩。

两者分开是有意的。给老师看的日志里塞满"Tk 的第三态"「路径公共前缀」，没人看
得下去；而只留一句"修复了选项显示问题"，半年后自己也想不起来到底改了什么。

## 命名

    docs/更新日志/<版本号>.md        例如 4.2.0.md

两条产品线共用这一个目录，版本号本身就区分得开（3.x 仿真环境，4.x 学生桌面端）。

## 一份该写什么

- **这次解决了什么问题**：从使用者的角度说，不是从代码的角度。
- **怎么做的**：关键取舍，以及为什么不选另一条路。
- **踩到的坑**：症状是什么、为什么难发现。这部分最值钱 —— 它是下一个人（多半
  还是你自己）唯一读得进去的东西。
- **验证**：测了什么、数据是多少。空口说"优化了性能"没有意义。
- **升级注意**：部署这一版要额外做什么（装依赖、改配置、重打 exe）。
