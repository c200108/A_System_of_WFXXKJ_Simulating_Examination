原来是 `DELETE FROM typing_records WHERE id IN (SELECT id FROM typing_records WHERE …)`。SQLite 认，
MySQL 报 1093（不能在子查询里读正在删的表），正式服务器上管理员、老师一点就「服务器出错了」。
现在先查出 id，再按 id 分批删（`recycle.delete_ids`），测试里断言生成的 SQL 不带子查询。

## 允许提前交卷

`exams.early_submit`（迁移 0019，默认关）。发布时可设，考试管理列表里随时开关（PATCH /api/exams/{id}）。
取卷接口（`/api/take/{token}`、学生平台取卷）和考试包 manifest 都带上 `early_submit`，
网页端 `submitGate.js`、学生端 `ExamFrame.gate_reason` 见到它就不拦。时间到自动交卷本来就不经过门槛。

**数据库会自动补字段**：容器启动时 entrypoint 本来就跑 `alembic upgrade head`，`git pull && sudo docker compose up -d --build` 即可。

**考试中途打开也要生效**（老师实际遇到：中途打开后学生还是交不了）。两处原因：考试包缓存的指纹里没有
`early_submit`，开关改了缓存不失效；答题页只在取卷时读一次。现在指纹带上它；新增
`GET /api/take/{token}/live`、`GET /api/student/exams/{id}/live`（只回 `early_submit`、`is_open`），
学生端和网页答题每 30 秒问一次，点「交卷」被门槛拦住时当场再问一次。问不到按原设置走，出错不弹窗。

## WPS 文字题逐题重写（`app/services/wps_bank.py`）

通用规则按句式猜，题干一复杂就和文档对不上（老师查出来的「悯农」：李绅那段只有半句、
「最后一段」不是最后一段、没有文本框）。题库里的 11 道 WPS 文字题现在按原题逐题写死：

- 题干引的原文（「……」两边）在文档里完整存在、独占一段；「最后一段」「第 N 自然段」位置对得上；
- 文本框（悯农）、大树图片（风中的一棵树）真的铺在文档里；要替换的词、要移动的段落都在；
- 初始格式不满足要求（要 A4 的先是 B5，要黑体的先是宋体……）；
- 每一问都有检查点。新增可判：文本框/图片/艺术字的尺寸和环绕、图片挨着某段、分栏和栏间距、页码、
  页面边框、页眉页脚对齐、下划线线型、上下边距一致、输出 PDF、移动不是复制；
- 字符格式按「每一截字」判（学生只选中字、没选中段落标记也判得准）。

旧数据（stem_to_sim 配的、导入的旧数据包）里通用规则生成的版本，出卷判分时自动换成写死的这份；
老师在仿真器里改过的不动。

验证：`tests/test_wps_bank.py` 逐题查「引文在文档里」「不做不得分」「照做满分」「写出去读回来一致」；
另用 LibreOffice 真的把 11 道题做了一遍、存成 .docx，学生端读回来全部满分。

网页版 WPS 仿真器没有文本框、图片、纸张大小、页码这些按钮，这几问在网页上做不了 —— 机房里用的是真 WPS，不受影响。

## WPS 文字题判分

- **输对了不得分**：题干解析（`stem._clean`）把「：」改成「:」、去掉空格，学生按题目打全角冒号就对不上
  （如「即时AI：即时AI是…」）；WPS 存盘后文末常多一个空段，又被当成「最后一段」。
  现在 `sim.loose_text()` 比对时统一全角半角（NFKC）、去掉空白和各式引号；`order` 检查忽略空段。
- **题干与文档对不上**：题干用括号抄原文（「第一自然段（人工智能……文化情景的有力支撑。）」）时，
  `_excerpt` 只认引号，这句话没进生成的文档。现在括号里带省略号的原文也认。
- **「第一自然段」指向标题**：生成文档第 0 段是标题，原来给的下标是 0，改为 1。

**已入库的题不用手动处理**：库里存的是旧规则生成的版本，恢复备份、导入旧 exam-data 数据包也会把旧版本带回来。
所以出卷、判分时（`exam._item_from_row`）用 `stem.refresh_wps()` 比一下：检查点除定位外和现在生成的一条不差、
文档名也一样，就是没被老师改过的，当场换成新规则重算的那份；老师改过的原样保留。不写库，导几次旧数据都一样生效。
