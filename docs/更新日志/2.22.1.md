# 服务端 2.22.1 —— 打字练习防作弊

发布：2026-11-11

起因：打字学情里出现「8340 字/分、用时 00:01」这类成绩，是把原文整段粘贴进输入框刷出来的。

## 网页打字端（`frontend/src/typingGuard.js`，/dazi 和学生平台的打字页共用）

- 输入框拦 `paste`、`drop`、`copy`、`cut`，`beforeinput` 里 `insertFromPaste / insertFromDrop / insertReplacementText` 等来源的输入一律拦；
  Ctrl/⌘ + V / C / X / A、Shift+Insert、Ctrl+Insert 拦；整页禁右键菜单；原文区 `user-select: none`，整页 `copy` 拦掉。
  输入框关掉自动完成、拼写检查、自动更正。
- 数按键：练习期间输入框里的 keydown（输入法拼音、五笔编码的按键也有 keydown，`key = Process`）计数，交成绩时报 `keystrokes`。
- 字数突变：两次 input 之间多出 2 个以上字，英文要求多出的字数 ≤ 期间按键数 + 1，中文要求期间至少按过键且一次不超过 30 字；不满足的撤回到上一次内容。
- 开发者工具：F12、Ctrl+Shift+I/J/C/K/E/M、Ctrl+U、Ctrl+S、⌘+⌥+I/J/C/U 在捕获阶段拦掉。
  开着开发者工具时 `debugger` 会停住，练习中每秒用 `new Function('debugger')` 计时探一次（>100ms 即判定打开），
  探到就作废这次练习、不交成绩；点「开始」时也先探一次。思路同开源的 disable-devtool / devtools-detect。

## 服务端（`routers/typing_train.py` 的 `_cheated`）

- 速度上限：中文正确字数每分钟 > `typing.max_speed_chinese`（默认 200）、英文 > `max_speed_english`（500）、
  键盘模块按键数每分钟 > `max_keys_per_min`（400）不收，返回 400 并说明原因。填 0 不限。
- 按键数核对：带了 `keystrokes` 且字数 ≥ 10 时，`keystrokes < 字数 × min_keys_per_char_*`（中文 0.6、英文 0.9）不收。
  exe 和旧网页不报按键数，只查速度上限。
- 已经入库的异常成绩不自动删，老师在「打字学情 → 成绩」按速度排序后删除。

## 验证

- `pytest tests/test_typing*.py`（新增 `test_typing_anticheat.py`）全过；前端 `npm run build` 通过。
