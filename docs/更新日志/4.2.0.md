# 4.2.0 —— 学生桌面端：界面对齐网页版，连接提速

发布：2026-09-20　｜　配套：仿真环境 3.2.0

这一版解决的是**部署到公网之后暴露出来的几个问题**：界面和网页端对不上、
配图不显示、打字能复制、连接慢。

---

## 一、界面照搬学生网页端

同一批学生，在家用网页、在机房用 exe，两边的菜单和说法对不上就会懵。所以：

```
左侧  🏠 首页    📝 考试    ⌨ 打字练习
右侧  内容区，打开默认停在首页
顶栏  姓名班级 · ⟳ 刷新 · 退出登录
```

登录方式从「考号 + 姓名」改成**学号 + 密码**（初始密码就是学号）。不改这一条
就做不了修改密码 —— 没有密码可改。

数据全部走网页端本来就有的 `/api/student/*`：首页数字、考试列表、打字练习，
和网页上看到的是同一份，不是另抄一遍。

**刷新按钮**：老师随时会发新考试，学生已经登录着，不该为了看见它去重开程序。

## 二、带图的题终于有图了

题库里 26 道题带配图，**全是 .jpg，而 Tkinter 只认 PNG 和 GIF**。题干写着
"请仔细读图"，学生屏幕上什么都没有 —— 这题谁也做不出来，而且考试当场才发现。

转换放在**服务端**（`app/services/images.py`）：学生端因此不用为了解码 JPEG
往 exe 里塞一个图像库，一张图也只转一次，全机房共用。

### 这里有个反直觉的坑

PNG 是**无损**格式。照片直接转过去会比原 JPEG 大一倍多：

| | 四张真题配图合计 |
|---|---|
| 原 JPEG | 194 KB |
| 直接转 PNG | **399 KB** |
| 减到 256 色 | 173 KB |

于是一份考试包从 300 KB 涨到 900 KB，五十个学生同时开考要传 45 MB。
减色之后比原图还小，而考试插图基本是图表和截图，肉眼看不出差别。

## 三、连接慢：量出来再改

学生报"刷新、打开考试都要等一段时间"。先量，不猜：

```
TCP 握手              50 ms
最轻的接口调用       100 ms   （= 握手 + 一个来回）
所有公开接口         ~90 ms   → 服务器本身不慢，是纯网络往返
实测带宽             ~6 Mbps
考试包               900 KB，服务器每次重建约 0.5 秒
```

结论：**服务器不慢，慢在"每个学生都重建一次包"和"包太大"。**

### 改了四处

| 改动 | 效果 |
|---|---|
| 服务端按版本缓存考试包 | 建包 451 ms → **1.9 ms**（第二个学生起） |
| 配图减色 | 包 900 KB → **385 KB** |
| ETag + 条件请求 | 学生重进考试：**0 字节**，一个来回 |
| 客户端连接复用 + gzip | 每次调用省一次握手（约 50 ms）；JSON 压缩后约剩三成 |

缓存的指纹取自考试、试卷、题目、仿真任务的最后修改时间 —— 老师改了卷子、换了
配图，包自动重建；没改就一直用缓存。**宁可多建一次，也不能发旧包。**

五十人同时开考的下载时间从约 58 秒降到约 25 秒。剩下的是带宽本身，只能靠错峰
（学生不会真在同一秒点开始）或者更宽的上行。

## 四、两个小而要紧的修复

**选择题一进题四个选项全是黑点。** Tk 的 Radiobutton 有个"第三态"：绑定变量
正好等于 `tristatevalue`（默认就是空串）时，它画成"值未定"的样子，在 Windows
上就是实心点。学生以为自己选过了。

现在两道保险一起上：变量初值给一个选项里绝不会出现的值，`tristatevalue` 也换
掉。只做后者其实就够，但这条坏掉的表现是"全班看见四个黑点"，而代码和测试都看
不出毛病 —— 多一道保险便宜。

**打字练习能复制粘贴。** 能复制原文粘到答题框，速度和正确率就都是假的。四条路
一起堵：Ctrl 快捷键（含大写）、中键粘贴、右键菜单、Tk 的 `<<Paste>>` 虚拟事件。
少堵一条就能绕过去。

## 五、登录页显示构建时间

机房里常常同时存在好几份 exe（ghost 过去的、U 盘拷的、上次留下的）。
"修好的问题怎么还在"十有八九是跑了旧的那份。构建时间显示在登录页左下角，
一眼就能对上，不用去比文件日期。
