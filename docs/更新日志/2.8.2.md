# 2.8.2 —— 交卷 500：答卷太大，数据库那一列装不下

发布：2026-09-21

机房里学生交卷，屏幕上：

```
交卷成功
本机备份：080606-金宗翰.ans　已记录考试文件夹里的 93 个对象
※ 答卷已存到本机，但没能上传
   服务器拒绝了（500）　卷子没丢，网络恢复后可以补传
```

**卷子没丢**（本机 .ans 在），但服务器那边一条记录都没有。

---

## 一、原因：MySQL 的 TEXT 只有 65535 字节

一道 Windows 操作题交上来的"终态"是**整个考试文件夹的快照** —— 每个文件的
路径、大小、时间、MD5，文本文件连内容一起。而一场考试里 win 题有好几道，
**每道都带一份完整快照**；`detail_json` 里还要把学生的作答原样回抄一遍。

照着老师那份题量实测（`backend/tools/验操作题.py` 铺的真实考场）：

| 考场对象数 | 操作题 | answers_json | detail_json |
|---:|---:|---:|---:|
| 41 | 4 | 22 KB | 30 KB |
| 60 | 6 | 43 KB | 53 KB |
| **93** | **11** | **90 KB** ✗ | **108 KB** ✗ |

`exam_submissions.answers_json` 和 `detail_json` 建表时是 `TEXT`，
**MySQL 的 TEXT 上限是 65535 字节**（不是字符 —— 中文一个字 3 字节）。
MySQL 8 默认严格模式，超了直接报 1406「Data too long」，整条 INSERT 失败，
接口上就是 500。

学生屏幕上那 **93 个对象**就是这一条的读数：考场越大、操作题越多，越必然撞上。

### 为什么测试一直是绿的

**SQLite 的 TEXT 没有长度上限。** 开发机和 CI 都跑 SQLite，一样的答卷写进去
安然无恙 —— 这件事只在正式服务器的 MySQL 上发生，而且发生在学生点「交卷」
那一刻，是最不该出问题的时候。

---

## 二、改法：那两列换成 LONGTEXT

```sql
ALTER TABLE exam_submissions MODIFY answers_json LONGTEXT NOT NULL;
ALTER TABLE exam_submissions MODIFY detail_json  LONGTEXT NOT NULL;
```

LONGTEXT 上限 4 GB，这条路上再也不会撞墙。迁移脚本 `0013_big_submission_json.py`
**只在 MySQL 上动手**：SQLite 那两列本来就没有上限，ALTER 反而要重建整张表。

models.py 里加了一个类型别名，以后新的大 JSON 列直接用它：

```python
BIG_JSON = Text().with_variant(LONGTEXT, "mysql")
```

只改了这两列。同表的 `manual_json` 是「题号 → 老师给的分」，大小由题量决定，
几百字节；仿真任务的 `env_json` / `checks_json` 实测最大 2.4 KB，都不动。

---

## 三、守住它

两条测试，都不需要真连一个 MySQL：

- `test_migrations.py::test_答卷的两列大JSON在MySQL上是LONGTEXT` ——
  按 MySQL 方言把 DDL 编译出来看一眼，不是 LONGTEXT 就挂。
- `test_exam.py::test_带整份考场快照的答卷交得上去` —— 造一份 76 KB 的答卷，
  交上去再从老师的阅卷接口读回来，**逐字节比对**，短一个字就是被截断了。

第二条在 SQLite 上永远绿，它真正的用处是 `TEST_DATABASE_URL` 指向 MySQL
跑那一趟（见 `tests/conftest.py` 开头）。迁移生成的 SQL 也离线核对过：

```bash
cd backend && DATABASE_URL="mysql+pymysql://u:p@h:3306/exam" alembic upgrade 0012:0013 --sql
```

---

## 升级注意

**服务器 `git pull && docker compose up -d --build` 即可**，容器启动时自动跑
`alembic upgrade head`，那两条 ALTER 会自己执行完。

已经存下来的答卷一条都不受影响（LONGTEXT 是加宽，不动数据）。

### 没传上去的那几份怎么补

答卷在学生机上，路径：

```
%LOCALAPPDATA%\信息技术考试客户端\答案包\学号-姓名.ans
```

服务器更新之后，在**那台学生机**上打开客户端，登录页右侧会出现「补传」按钮
（有待传答卷时才显示），点一下就传上去了。

**补传前先确认这场考试还是「开启」状态** —— 关掉的考试不收卷（403）。
交卷记录里的成绩、姓名、学号都从 .ans 里读，和当场交卷完全一样。
