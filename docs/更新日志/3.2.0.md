# 3.2.0 —— 操作题逻辑改为以题干为准

发布：2026-09-20　｜　配套：学生桌面端 4.2.0

## 问题

老师把 2.8.0 的数据用 `data-export.sh` 导出，再 `data-import.sh` 导进 4.x 的
新库。导完之后学生端打开考试，**三类操作题全变成了"拖拽题（热区/流程图）"
占位**：Windows 操作、WPS 文字、AI 工具，一道都不能做。

原因是旧库里 `questions.sim_task_id` 全是空。系统当时只认数据库里配好的仿真
任务，没配的就当作"不知道怎么判"，于是整批操作题一夜之间失效。

**最糟的是它表面上看不出毛病**：题目照出、考试照发、学生照样能交卷，
考完才发现操作题全是 0 分。

## 改法

把判断依据从"数据库里配了什么"换成"**题干写了什么**"。

题干是跟着题目走的，导库不会丢。中考信息技术的题干写法又高度统一：

```
本题工作目录:D:\EXAM\windows操作
①在"IT"文件夹下创建"计算机技术.docx"文件。
②将"IT"文件夹下的文件"遥感.txt"和"红外.txt"移动到"传感技术"文件夹中。
```

一句一个操作，动词就那么几个。所以能直接算出**开考铺什么文件**和**交卷查什么**。

挂载点只有一个：`app/services/exam.py` 的 `_item_from_row()`。这是题目从数据库
变成"完整一题"的唯一入口，出包和判分都要经过它。在这里兜底，两边自动一致 ——
不可能出现"铺了文件却没有检查点"或者反过来。

```
q.sim_task 有      → 用老师配的（他调过的更准）
q.sim_task 没有    → stem.auto_sim(题干, 知识范围) 当场推
两种都推不出来     → 才算真的不能自动判分
```

## 为什么检查点不能放到 exe 里算

学生端拿得到的东西等于公开。检查点就是答案 —— 「在『IT』里建一个
『计算机技术.docx』」这句话本身没什么，但一整套检查点摆在学生机上，
等于把评分标准发下去了。

所以分两头：**环境在出包时由服务端按题干生成**（文件跟着考试包下发），
**检查点在判分时由服务端按同一个题干生成**。两头调的是同一个函数、同一段题干，
结果必然一致，而答案一个字都没离开服务器。

## 顺带

题目配图统一压缩成限定尺寸和色彩的 PNG。PNG 是无损格式，照片直接转过去会比原
JPEG 大一倍多（实测 194 KB → 399 KB）；减到 256 色之后只剩 173 KB，比原图还小，
而考试插图基本是图表和截图，看不出差别。

## 验证

`backend/tests/test_sim_fallback.py` 用的就是学生截图里报上来的那三道题的原文，
断言在**没有仿真任务**的前提下：

- 三道题都认得出类型（win / wps / ai），不再掉进拖拽题占位
- Windows 题真把 `遥感.txt`、`红外.txt`、`传感技术` 铺了出来
- WPS 题铺出真 `.docx`，而且**要替换的那个词真的在正文里**（否则学生找不到要
  替换的东西，这一问谁也做不出来）
- 交卷即自动判分，做错了逐条指出是哪一步
- **考试包里依然没有任何检查点**
- 老师手工配过的仍然优先，兜底不会把他的配置盖掉

另有 `backend/tools/检查操作题.py` 可以随时给题库体检：拿真题走一遍铺考场、
照检查点做对、判分，哪道题发出去会出事一眼看见。
