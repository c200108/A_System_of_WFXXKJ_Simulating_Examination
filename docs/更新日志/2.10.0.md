## 一、成绩分析（`services/analysis.py`、`views/ExamAnalysis.vue`）

成绩页头上的「成绩分析」、考试列表的「分析」都新开一个标签页（`/js/analysis/{考试 id}`）。

**看谁**：全体参考学生 / 选几个班 / 选最多 8 个学生对比。选择记在地址栏里，把链接发给
别的老师，打开就是同一个视角。

**指标**：参考人数、平均分（得分率）、中位数、最高最低、标准差、及格率、优秀率（≥85%）、
低分率（<40%）、满分人数、待复核份数。

**图**（每张都能展开看原始数字）：分数段分布、知识范围掌握、班级对比（平均得分率 / 及格率 /
优秀率）、各班箱线图、每题得分率、大题得分率、难度与区分度、操作题每一步的通过率、名次表；
学生对比时另有按知识范围、按大题的分组柱。

**结论**是服务端按数据写的，老师能直接拿去讲评：整体水平和及格情况、分布形状和离散程度、
班级差距、最薄弱的知识范围、得分率最低的题、区分度偏低（可能有歧义）的题、操作题卡在哪一步、
每个被比较学生的名次和强弱项、两人差距最大在哪。还有答卷待复核时会说清楚"数字按当前得分算"。

**跟着阅卷变**：页面每 20 秒重拉一次（切到别的标签页时暂停），老师在成绩页阅完一份，
这边的数和结论自己就变了。实测：成绩页给一份卷子评完分，20 秒后分析页「待复核」26→25、
平均分 55.7→56。

### 几个口径

- 卷面总分不一定是 100，比较、划线都按得分率；及格线取 config.yaml 的 `exam.pass_score`。
- 区分度：按总分取前 27% 和后 27%，这道题两组得分率之差。
- 没设分值的老卷子（2.4.0 以前）按客观题正确率折百分制，操作题不计分 —— 结论里不说
  "操作题平均得分率"，也不报待复核。

### 图的规矩

一张图只有一个纵轴（班级对比三项都是百分比，放一个轴上）；分类色按固定顺序取，深浅色各
一套（配色过了色觉障碍检查）；两个以上系列有图例；图下面都能看原始数字。

### 性能

每份答卷的明细（带考场快照的一份上百 KB）只解析一次。60 份卷、67 道题：1455 ms → 97 ms。

**图表库 ECharts 单独一块**，只有分析页才加载 —— 混进公共块的话，每个页面（包括五十台机器
同时打开的考试页）都得先下 500 KB。

## 二、成绩页

- 按班筛、按姓名学号搜、总分列点表头升降序，都在前端做（一场最多几百份，全拿下来比每敲
  一个字问一次服务器快）；
- 删答卷：单删、勾选批量删。**要改得动这场考试**（自己发的，或者管理员）—— 管理员发的全校
  统考，任课老师能看能批，不能删。删掉之后这个学生可以重新交卷。批量删只认这场考试自己的
  答卷 id；
- 「样卷」：带答案，只走教师接口。

顺带修掉一条死路：**没设分值的老卷子**，成绩表照样显示「阅卷 12」，点进去保存又被拒绝
（400「这份卷子没有要人工评阅的题」）。这类卷子操作题不计分，现在不显示待阅。

## 三、操作题：全过 / 全没过不用老师再点（3.5.1）

按检查点判完之后（`services/exam.py` 的 `settle_auto`）：

| 检查点 | 分数 | 算不算评完 |
|---|---|---|
| 全部通过 | 满分 | 算，老师不用管 |
| 全部没过 | 0 分 | 算，老师不用管 |
| 部分通过 | 按比例预填 | 不算，老师看一眼点保存（可以改） |

老师已经给过分的题（`graded` 且不是系统定的）一律不动；老师保存时没带上系统定好的分，也不会
把它清零。**老答卷**在升级后第一次启动时补一遍（只补一次，记在 `app_meta`），分数本来就是
满分 / 0，只是标成评完，「待阅」随之消失。

## 四、系统时间校正（`app/clock.py`、`config.yaml` 的 `time.offset_hours`）

服务器时钟快了 8 小时又改不了系统时间：config.yaml 里

```yaml
time:
  offset_hours: -8
```

`docker compose restart backend`。

- 之后所有"现在"都取 `clock.now()` = 服务器时间 + 校正值（交卷、阅卷、建账号、导入……）；
- **已有记录的时间在重启时一起挪同样的差值**（容器启动跑 seed 时、服务接请求之前），挪到了
  多少记在新表 `app_meta`（迁移 0015），没改就不再挪。改成 -7 就整体再挪 +1；
- `app_meta` 不跟着数据导出导入 —— 它说的是这台机器的时钟。导出来的时间是校正过的，导到
  机房版（校正值 0）就是对的；
- 登录令牌的过期时间照旧用 UTC（同一台服务器自己签自己验，和显示无关）。

**注意**：要是以后服务器时钟被修好了，把 `offset_hours` 改回 0 会让已有记录**再挪 +8 小时**
（系统以为那些时间是按 -8 记的）。那种情况先别改配置，找维护的人。

## 五、机房版：Win7 上启动服务崩（机房版仓库）

`DLL load failed while importing _bcrypt: 找不到指定的程序`。wheels 里的 bcrypt 5.0.0、
cryptography 47.0.0 是 Rust 编的，Rust 1.78 起不支持 Win7：导入表里有
`bcryptprimitives.dll!ProcessPrng`（Win10）和 `WaitOnAddress` 一族（Win8）。开发机和测试
全过，首次安装也装得完，一启动服务就崩。

换成 bcrypt 4.0.1（2022 年编的，导入表干净，哈希格式一样），去掉 cryptography（机房版用不着）；
首次安装装完会把程序整个导入一遍，这类问题在装机时就报。机房版新增 `工具\查Win7兼容.py`，
换 wheels 之后必跑。

## 升级注意

- 服务器：`git pull && sudo docker compose up -d --build`。**仓库是私有的**，pull 要只读令牌
  （见 2.9.0.md 最后一节）。迁移 0015 自动跑；老答卷的操作题补评在第一次启动时自动做。
- 服务器时钟不准的：改 config.yaml 的 `time.offset_hours`，`docker compose restart backend`。
- 机房版：下载新版覆盖，再双击一次「首次安装.bat」。
