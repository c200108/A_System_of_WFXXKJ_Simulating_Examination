# 服务端 2.23.1 / 学生端 4.14.2 —— 堵上打字成绩伪造

发布：2026-11-19

起因：交打字成绩的 `POST /api/typing/records` 只收「敲了多少、对了多少、用了多久」三个统计数，
速度、正确率由服务端算，但这三个数是客户端说了算 —— 不用打字，一个请求就能造出任意成绩。
2.22.1 的速度上限和按键数核对挡得住整段粘贴，挡不住直接改数字。

## 新协议（`routers/typing_train.py` 的「计分会话」一节）

1. `POST /api/typing/sessions {module, difficulty, time_limit, student_name, student_class}`：开练。
   服务端出文本（键盘模块是固定的键位串）、记开始时间，回 `{session_id, text, sync_interval_sec}`。
   `session_id` 是 32 字节随机串，当凭据用，不放网址里。名单校验从交成绩提前到开练。
2. `POST /api/typing/sessions/progress {session_id, answer}`：练习中每 1.5 秒同步一次输入框全部内容
   （键盘模块是按过的键依次排成的串）。服务端按时间窗看平均速度：从之前任何一个同步打点到现在，
   多出来的正确字数 ≤ 上限 × 时长 + `burst_chars`（默认 30，给输入法整句上屏、断网补传留的）。
   超了就作废这个会话（以后同步、交成绩都回同一句原因）。网络错误、5xx、429 客户端不管，下次再同步。
3. `POST /api/typing/records {session_id, answer, keystrokes?}`：交成绩。班级姓名、模块难度、原文、
   用时都以会话为准，请求里带的统计数一律不看；没带 `session_id` 的（旧网页、旧 exe）回 400
   「学生端版本太旧，交不了成绩：请刷新网页或更新学生端后重新练习」。

## 用时

- 按服务端的钟算。限时练习：从开练算起；到点后 `submit_grace_sec`（默认 10 秒）内交上来的照收，
  用时最多算到「时限 + 宽限」；再晚才交（断网）只认到点前最后一次同步上来的内容，用时按「时限 + 宽限」。
  到点后的同步不收。
- 不限时（exe）：从第一次同步上来有字的那一刻往前倒推 3 秒算开始，看文本的时间不算。
- 被「每分钟只能交一次」挡回来（429）的，第一次交时就把内容和用时定下来存住，客户端倒数完再交，
  用的是存住的那份，等的时间不算、再交时多塞的字也不认。

## 一次性、限频、清理

- 一个会话只能交一次：`UPDATE typing_sessions SET used=1 WHERE id=? AND used=0`，改到 1 行的那个请求才入库。
- 开练按出口 IP 限频（`sessions_per_ip_per_minute`，默认每分钟 120 次，要大于一个机房的人数），
  设备号是客户端自己报的，脚本随手换；中文英文另外照旧占「每分钟最多换 3 次文本」。
- 会话 2 小时内有效；开练时顺手删掉 3 小时以前的。`typing_sessions` 不进数据备份（`tools/export_data.py`、
  `import_data.py` 的 `SKIP_TABLES`），也不进回收站快照。
- 不再按学号认领成绩（只报个学号就能把成绩挂到别人名下）：带令牌的以账号为准；令牌过期的按
  开练时填的班级姓名对名单认领。

## 客户端

- 网页（`frontend/src/typingSession.js`，/dazi 和学生平台共用）：开练领会话、每 1.5 秒同步（输入法组字时不同步）、
  交成绩带 `keystrokes`。服务端回作废就停表提示。2.22.1 的 `typingGuard.js` 照旧。
- 学生端 exe 4.14.2（`desktop/client/api.py`、`ui.py`）：「换一段」就是领新会话，取过的会话照旧缓存
  （切页不重新领）；每 1.5 秒同步；交完一次自动换一段新的。

## 部署

新增迁移 `0025_typing_sessions`。**服务端和新 exe 要同一天换上**：新服务端不收旧 exe 的打字成绩
（会提示更新学生端），旧服务端也不认新 exe。网页刷新一下就是新的。

## 边界

免登录页（/dazi）的班级姓名仍然只能信学生自己填的；能写程序按正常速度模拟敲键、按节奏同步的也挡不住。
这次堵的是「改个数字就交上去」和「整段粘贴 / 一次塞进去」。
