# 4.3.0 —— 学生桌面端：只发一个 exe

发布：2026-09-20　｜　配套：仿真环境 3.2.0（本版未改动服务端）

上一版的分发方式是"把「发布」文件夹整个 ghost 到全机房"。这一版改成**拷一个
文件过去就行** —— 桌面、U 盘、网络共享都可以，双击即用。

---

## 为什么原来必须发文件夹

不是没想过只发 exe，是当时发不了。三件事挡着，缺一件都得把文件夹带上：

| 挡路的 | 症状 |
|---|---|
| exe 旁边会自己长出东西 | 程序一跑就在同目录生成 `客户端设置.json` 和「答案包」文件夹 —— 拷过去的"一个文件"当场变成一堆 |
| 教师端地址没地方带 | 地址记在同目录的设置文件里。不带文件夹，每台机器都得人工输一次 |
| 只读位置跑不起来 | exe 放在网络共享或被组策略锁住的桌面上，往旁边写直接失败 |

三件一起解，才谈得上"只发一个 exe"。

---

## 一、运行数据搬到用户目录

设置、答题草稿、答案备份（`.ans`）、考试记录（`考试记录.csv`）统一写到：

```
%LOCALAPPDATA%\信息技术考试客户端\
```

拿不到 `LOCALAPPDATA` 就退到 `APPDATA`，再退到临时目录；三个都写不了才退回 exe
所在目录 —— 极端情况宁可退化，也不能让学生考不成试。

顺带解决了第三条：**exe 放在只读位置也能跑**。

**原来那种部署不受影响。** exe 旁边如果已经有 `客户端设置.json`，仍然优先用它 ——
早先整个文件夹 ghost 出去的机器换上新 exe 之后，不该突然忘掉教师端地址。

---

## 二、教师端地址跟着 exe 走

三种带法，按优先级从高到低：

| 带法 | 怎么做 | 适合 |
|---|---|---|
| **写在文件名里** | 改名成 `考试客户端@192.168.1.8_8080.exe` | 教师端换了 IP —— **改个名就行，不用重新打包** |
| **本机记录** | 学生在登录页输一次 | 临时用一台机器 |
| **打包时烤进去** | `python build.py --server 192.168.1.8:8080` | 机房统一装机，学生双击就能用 |

命令行 `--server` 比这三个都高。冒号在 Windows 文件名里非法，所以端口前用下划线。

**文件名排在本机记录前面是故意的**：网管刚改的名是最新的决定，不该被各机器上那个
过期的保存值顶掉。

打包完成后 exe 会自动带上地址后缀：

```
发布\考试客户端@111.170.33.3_3315.exe
```

机房里拿到的那一个文件，自己说明自己连哪儿。

## 三、装机自检报出"这台机器会连哪儿"

`--selftest` 的报告最后多了一段：

```
教师端地址：http://111.170.33.3:3315
    文件名 111.170.33.3:3315　｜　本机记录 无　｜　打包内置 111.170.33.3:3315
```

地址有了三个来源，机房里就会出现"对不上"的情况 —— 网管改了文件名，而某台机器上
还留着上学期的记录。三个都写出来，谁盖住谁一目了然，不用一台台开窗口看。

---

## 四、打包脚本两处加固

**上一版还开着时不再打断打包。** 正在运行的 exe 删不掉，但改得了名 —— 现在挪到
一边，下次打包再清。原来这种情况直接抛 `PermissionError`，整次打包白跑，而原因
只是"忘了关窗口"。

**控制台编码不再让打包崩掉。** Windows 控制台默认 GBK，提示语里一个 `⚠` 就能让
打包停在第一步。打包脚本不该因为一行提示语失败。

## 升级注意

1. **exe 要重打并重新分发**，本版改动全在客户端：

   ```
   python desktop/build.py --server 111.170.33.3:3315
   ```

2. 老机器上 exe 旁边的 `客户端设置.json` 可以留着，也可以删掉 —— 删掉后走内置
   地址或文件名地址。
3. 已经收上来的 `.ans` 答案包仍在原「发布\答案包」目录，不会被新版本移动；
   新产生的答案包写到 `%LOCALAPPDATA%\信息技术考试客户端\答案包\`。
