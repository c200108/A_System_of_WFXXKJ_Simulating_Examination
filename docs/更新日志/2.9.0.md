# 2.9.0 —— 服务器和机房版互相导数据：导得过去，一样不少

发布：2026-09-23

要求很简单：机房版（Win7，SQLite）和服务器（MySQL）的数据能来回导，不出错、不丢东西。
拿机房版的真实库走了一遍，四个问题，其中两个**已经在丢数据**：

| | 症状 | 丢没丢 |
|---|---|---|
| 1 | 配图一张都过不去（哪个方向都是） | **丢** —— 表导进去了，带图的题没图，一句提示都没有 |
| 2 | 机房版的时间比北京时间早 8 小时 | 时间错 —— 8:10 导的名单记成 0:10 |
| 3 | SQLite 装得下、MySQL 装不下的数据，一条就让整个导入失败 | 不丢，但导不进去，报错还只说第一条 |
| 4 | 看不懂的时间被悄悄存成空 | **丢** |

## 一、配图：两边各打各的包，各认各的

服务器 `data-export.sh` 在宿主机上 `tar czf` 出 `uploads.tar.gz`；机房版自己用
zipfile 打 `uploads.zip`。导入时**各自只找自己那种**：

- 服务器的备份 → 机房版：报一句「备份里没有 uploads.zip，配图没还原」，往下走了；
- 机房版的备份 → 服务器：`[ -s uploads.tar.gz ]` 不成立，**一声不吭**跳过。

两种情况下表都导得好好的，所以谁也没发现 —— 直到打开一道带图的题。

**改法**：打包和还原收进 `tools/uploads_archive.py`，由 `export_data.py` / `import_data.py`
调用。服务器和机房版走的是同一段代码，从根上就不可能再各打各的。

- 写：一律 `uploads.tar.gz`，成员名 `uploads/<相对路径>`，和服务器原来的布局一样；
- 读：`.tar.gz` 和 `.zip` 都认，带不带 `uploads/` 前缀都认（老机房版的 zip 就不带）；
- 还原是**合并**：备份里有的写进去，本机有、备份里没有的**一个不删**。原来服务器
  那边是先 `rm -rf data/uploads` 再解包，备份里少一张，本机就少一张；
- 包里的 `..`、绝对路径、盘符一律跳过，解不出考试文件夹以外的地方去。

服务器上 `data/uploads` 是挂载进容器的，所以在容器里打包、还原，宿主机上就有了。

## 二、时间：SQLite 的 now() 是 UTC

所有 `created_at` 都是 `server_default=func.now()` —— 由数据库给时间。

| | now() 给的是 |
|---|---|
| MySQL（容器 `TZ=Asia/Shanghai`） | 北京时间 |
| SQLite `CURRENT_TIMESTAMP` | **UTC** |

所以机房版里建的每一行都早 8 小时。更乱的是同一行里两种时间混着：答卷的
`submitted_at` 是数据库给的（UTC），`graded_at` 是程序 `datetime.now()` 给的（北京时间）。

发现它是因为学生名单：机房那台机器 08:05 导出过一次数据，紧接着导了名单，库里记的
却是 00:10。

**改法**：`models.py` 里所有时间列加 `default=now_local`（本机时间、去掉微秒），
`onupdate` 同理。程序给的值优先于 `server_default`，两个库就一致了。`server_default`
留着，给绕过程序直接写 SQL 的情况兜底。

去掉微秒是因为 MySQL 的 DATETIME 只到秒，**而且四舍五入** —— 23:59:59.6 进到第二天。
导入 MySQL 时同样先截掉。

机房版已有的老数据要修一次，工具在机房版仓库（`工具\修正时间.py`），服务器这边
不需要。

## 三、SQLite 什么都收，MySQL 有规矩

| | SQLite | MySQL（strict 模式） |
|---|---|---|
| VARCHAR(32) 存 72 个字 | 照存 | 1406 Data too long |
| TEXT 存 70 KB | 照存 | 1406（TEXT 只有 65535 字节） |
| 唯一键 `admin` 和 `ADMIN ` | 两行 | 1062 撞车（utf8mb4_unicode_ci 不分大小写、不管结尾空格） |

机房版里建出来的数据只要有一条撞上，导进服务器时整个事务回滚 —— 一行都进不去，
报错只说第一条，改一条再撞下一条。

**改法**：

1. `import_data.py` 写库前逐行体检，照**目标库实际的列类型**（从库里读，不看模型）
   算容量、按 MySQL 的比较规则找唯一键冲突；主键重复、时间看不懂也在这一步查。
   有问题就全部列出来（表、id、列、超了多少），返回 2，**一个字不写**。
   不替人截断 —— 截断就是丢数据。
2. 其余 14 个 TEXT 列在 MySQL 上全部改成 LONGTEXT（迁移 0014，只动 MySQL），两边容量
   一致，"装不下"只剩 VARCHAR 这一种可能。0013 已经改过答卷那两列。

## 四、导入是「还原」：会清掉什么，试算时就说

`import_data` 先清空同名表再填，本机有、备份里没有的行导完就没了。以前试算不提这件事。

现在试算逐表列出这个数。机房考完带成绩回服务器、而服务器这几天也有人在线考过 ——
这时候就会看到 `exam_submissions  37 行`，知道该停下来想想以哪边为准。

**没有做合并**。两个库的 id 各自往上长，同一个学生两边 id 不同，答卷里的题目 id
又写在 JSON 里 —— 合并要做整套 id 映射，做错了比丢数据更难查。先把"会丢什么"
说清楚，要不要合并等真有这个需要再议。

## 五、整个文件夹拷到另一台电脑：No Python at 'C:\Users\czr\...'

机房版是整个文件夹压缩了拷到机房的，里面带着 `backend\.venv` —— 在开发机上建的运行
环境。**venv 只能在建它的那台电脑上用**：`pyvenv.cfg` 里记着那台电脑上 Python 的完整
路径，启动器照着它去找 python.exe。换台电脑，那个路径不存在：

```
[1/4] 用的 Python：C:\Users\Administrator\...\Python38\python.exe   ← 机房这台找对了
[2/4] 准备运行环境……
No Python at 'C:\Users\czr\...\Python38-32\python.exe'               ← venv 还是开发机那个
[错误] 依赖安装失败。wheels 文件夹是不是没拷全？                        ← 提示还指错了方向
```

「首次安装」原来的逻辑是"`.venv` 在就不建"，于是一直用那个坏的。

**改法**：

- 「首次安装」先让 `.venv` 里的 python 跑一句，跑不起来就删掉、用本机 Python 重建
  （不联网，从 `wheels\` 装；`.env` 和库都不动）。删不掉（有窗口占着）就说清楚让人手删；
- 找 Python 的地方加了给所有用户装的（Program Files）和 `py -3.8` 启动器；
- 启动服务、一键导入 / 导出、改学生端地址四个脚本也先试一下，坏了就说「先双击首次安装」，
  不再甩出一句 No Python at；
- 主项目这边：`scripts/run-backend.bat` 同样先试，坏了给出重建命令；
  `tools/检查操作题.py`、`desktop/发版.py` 里写死的 `D:\Pythonproject\…`、
  `C:\Users\czr\…` 换成按文件位置 / `%LOCALAPPDATA%` 找。

在一份拷贝上照原样复现（把 `pyvenv.cfg` 的 home 指到一台"别的电脑"上），报的是同一句
No Python at；新的「首次安装」认出来、重建、装依赖、迁移、seed，退出码 0。

**拷的时候带不带 `.venv` 都行**，带着也会被重建。数据在 `backend\data\`、配置在
`backend\.env`，这两样要带；都是相对路径，放到哪个盘哪个文件夹都认。

### 仓库私有之后，服务器怎么 pull

服务器上的 `origin` 是 https 地址，私有仓库 pull 时会要用户名和密码 —— GitHub 已经
不收账号密码，要一个**只读的访问令牌**：

1. GitHub → Settings → Developer settings → Fine-grained tokens → Generate new token；
   Repository access 只选这一个仓库，Permissions 里 Contents 设为 **Read-only**；
2. 服务器上 `git pull` 时用户名填 GitHub 账号，密码处粘贴这个令牌；
3. 不想每次都粘：`git config credential.helper store`，下次 pull 输一次就记住了
   （明文存在服务器上 `~/.git-credentials`，所以令牌只给只读、只给这一个仓库）。

也可以改用部署密钥（Settings → Deploy keys，只读），`origin` 换成 ssh 地址。
