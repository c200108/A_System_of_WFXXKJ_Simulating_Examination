### 图是重画的，不是原截图

题库里这类题的配图是**原考试系统的截图**：素材区烤在图上方，说明弹窗还挡着半张
图（有的连「热区」两个字都被挡住）。直接拿来当底图，学生看到的是两层界面叠在一起。

所以每道题的结构图都照着原图**用框、线、热区重画了一遍**（`backend/app/services/drag.py`），
exe 用 Tk 画布画、网页用 SVG 画，同一份数据，两边长一个样。旧截图出卷时不再发。

## 二、题干不全的，补成明确的；原题干一个字不动

有几道题的题干根本没法作答：

```
Q324   （题干见图）
Q334   请将符合智能家居的设备拖拽到指定区域。
Q310   请点击"开始操作"进入Windows仿真系统，查询本机IP地址。
C0580  请打开本题工作目录（C：\EXAM\Python）中的"exam01.py"文件……   ← 这个文件根本不存在
```

每道都在清单里配了一段**补全后的题干**，出卷时替换掉原题干。补全的原则：只把图上
本来就有的信息、答题要做的动作写清楚，不改考点。比如 Q324 补成「输入两个正整数
a、b：如果 a 大于或等于 b，输出 a 减 b 的差；否则，输出 a 加 b 的和……」—— 这就是
原图说明弹窗里那段话。

### 为什么 data-import 导回旧数据之后也不会变

**清单写在代码里，按题干认题，不存进数据库。**

导回旧数据时，题目一行行被覆盖 —— 但题干还是原来那段话，所以认出来的还是同一道题、
同一张图、同一套检查点。补全后的题干也是在出卷那一刻才替换上去的，库里存的一直是
原题干。**要是把补全的题干写回库里，下次导库就会被旧题干覆盖回去**，而且改了题干
之后就再也认不出这道题了。

测试里存着这 24 道题**在题库里的原文**（`tests/test_drag.py` 的 `REAL_STEMS`），
逐一验证认得出、画得出、照答案做能满分。

## 四、判分怎么判

学生交上来的是「哪张卡片放在哪个热区」：

```json
{"placed": {"A": ["i1"], "B": ["i3"]}}
```

三种检查点：

| 检查点 | 意思 | 用在 |
|---|---|---|
| `slot` | 这个热区放的是这张卡片 | 流程图、位置固定的结构图 |
| `in` | 这张卡片放进了这几个热区中的任意一个 | 顺序不限的（两个智能设备谁左谁右都行） |
| `none_of` | 这几张干扰卡片一张都没放进来 | 归类题（把交换机拖进"智能家居"要扣分） |
| `ip` | 填的地址是本机真实地址之一（exe）或仿真地址（网页） | IP 查询 |

**素材卡片的 id（i1、i2…）按原图素材区的顺序排**，和答案无关，看包里的 id 猜不出答案。
检查点（答案）只在服务端；发给学生的图里没有 `op`、`assert` 这些字段，测试逐题守着。

IP 题的**仿真地址不进 exe 的考试包**：那是网页端仿真命令行显示用的，exe 查的是真机。
留在包里的话，学生把考试包解压开就能抄到一个"对"的答案。

反过来，exe 交上来的作答里带着本机的真实地址，这时**只认真地址**：仿真地址是固定的，
练过网页版的学生都见过，在机房里照抄它不算查过了。交卷时万一没查到本机地址（极少见），
这一条判不了，阅卷页写「请老师核对」，不冒充"填错了"。

## 五、顺带修的

### win04：「长江中下游平原」文件夹没生成

```
（2）在"长江中下游平原"文件夹中，将按名称排序后的中间一个文件改名为"长江三角洲.doc"。
```

这一问整句没有规则认得，而兜底"题干点过名的都补铺"那一层**恰好跳过了句子自己的
那个文件夹**（本意是别把它铺进它自己里面），于是哪儿都没铺。

现在铺出文件夹和三个文件：`巢湖平原.doc`、`江汉平原.doc`、`鄱阳湖平原.doc`，
中间那个是江汉平原。**名字是挑过的**：中文 Windows 的资源管理器按拼音排序，程序
按字符编码排序，两者经常不一致（「太湖」编码最小、拼音却靠后）。这三个名字两种
排法结果一样，学生照着屏幕改对了，判分也认。

### 「标题」样式：用「标题 1」被判错

两层原因，这一版都改了：

1. **桌面端读错了样式**：WPS 存 .docx 时样式编号是数字（"2" 就是它的「标题 1」），
   桌面端原来直接拿编号当名字，于是报「样式是 2」。现在按 styles.xml 里记的**名字**认。
   同一个 "2" 在中文 Word 里是「标题 2」，所以**不能按编号猜**，测试里两种都钉着。
2. **题干说「标题」样式**：Word 里叫「标题」的是 Title，可 WPS 样式栏最前面的是
   「标题 1」，老师学生说"标题样式"多半指它 —— 现在两个都算对。题干明确写「标题 1」
   的还是只认「标题 1」。

### 服务端升级后，学生机可能还在用旧考试包

考试包缓存的"指纹"原来只看数据库（题目、卷子的修改时间），而考试包的内容是**程序
按题干现算**的。程序升级了、库没动，指纹不变，学生机拿着旧包来问，服务器回 304 ——
考的还是旧题（比如少了一个文件夹的那一版）。现在指纹里加上了生成考试包那几段代码的
指纹，升级后自动作废。

## 升级注意

服务器 `git pull && docker compose up -d --build` 即可，不用改题库、不用重新导数据。

学生端要换 **4.8.0** 的 exe 才能在机房里做拖拽题。还没换的机器不会出事：

- 旧 exe（4.7 及以前）看到拖拽题，还是那块「作答区（待开发）」，可以先做别的题，
  交卷不受影响；
- 它交上来的这一题是个空作答 `{"state": {}}`（它收集作答时不认 drag，给的是空的）。
  服务端认得出来，**不自动判 0 分**，照旧留给老师评阅，阅卷页写着「没有拖拽作答
  数据（旧版桌面端做不了这类题）」；
- 新 exe 一张卡片都没放、网页端碰都没碰的，照常判 0 分（老师可复核），和别的操作题
  一样 —— 那是学生有机会做而没做。

要是不照这样分开，服务端升级、exe 还没换的那段时间里，机房每个学生的拖拽题都会
是一个标着"自动判分"的 0 分。
