# 服务端 2.23.0 —— 一键更新先比版本、下载学生客户端、API 多选、反馈黄条

发布：2026-11-18

## 一键更新先比版本（只在线版）

`scripts/host-agent.sh` 的 `update-github` 在下载前先 `check_latest`：

1. 本机提交号：`data/host-jobs/deployed-commit`。每次升级成功后，从压缩包注释里取（GitHub 打的 main 压缩包注释就是 40 位提交号；上传的压缩包也一样）。
2. GitHub 上的提交号：`git ls-remote`（顺着 `setup-github-cn.sh` 配的 insteadOf 加速），问不到再用 `api.github.com/.../commits/main`。
3. 两个都有：一样就写 `uptodate` 记号、状态「已经是最新版本（服务端 x.y.z），不用更新」，不下载；不一样就照常下载升级。
4. 本机没记过提交号（这个功能之前升级的）：比本机和 GitHub 上 `backend/app/changelog_seed.py` 里的全部版本号，一样也算最新，并顺手记下提交号。
5. 都问不到：照常下载（和以前一样）。

地址可以用 `UPDATE_GIT_URL` / `UPDATE_API_URL` / `UPDATE_SEED_URL` 覆盖（测试用）。
`/api/system/status` 新增 `version`（本机代码的 2.x 版本）和 `commit`。

**主机助手是从项目目录里跑的，所以这次要先用老办法升级一次（命令行或一键更新），新逻辑才生效。**

## 下载学生最新客户端（只在线版）

`SystemMaintenance.vue`：浏览器直接请求 `api.github.com/repos/…/releases/latest`，按联网版 / 机房版分组列出 exe，标出 Win7 该下的 32 位内置运行库版。连不上 GitHub 时给发布页链接。不经过学校服务器。

## API 多选

`POST /api/data-apis/bulk {ids, action: pause|resume|delete|transfer, owner_id}`：老师只动自己的，管理员动全部；`transfer` 只给管理员；看不到的进 `failed`。删除进回收站。网页 `DataApis.vue` 加「多选」。

## 反馈黄条

`GET /api/feedback/news`（登录的老师）：最近 24 小时里最新的一件公开的事 —— 反馈审核通过（按 `reviewed_at`）或已公开反馈下的新回复，返回 `{kind, id, author, text, at, until}`。`components/FeedbackNews.vue` 放在 `Paper.vue` 顶上，× 关掉的记在 localStorage（按消息 id），打印时不显示。
