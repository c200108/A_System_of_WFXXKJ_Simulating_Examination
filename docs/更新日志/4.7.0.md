# 4.7.0 —— Win7 上打不开：运行库带错了

发布：2026-09-21　｜　同期：仿真环境 3.4.0

学生机（Win7 SP1）双击 exe 弹错：

```
64 位 → 无法启动此程序，因为计算机中丢失 api-ms-win-core-sysinfo-l1-2-0.dll
32 位 → Error loading Python DLL '…\_MEI28082\python38.dll'
        LoadLibrary: 找不到指定的程序
```

两个错，一个原因。

---

## 一、原因：把 Win11 的运行库发到了 Win7

PyInstaller 打包时会顺手把**打包机上的**通用 C 运行库（UCRT）收进包里。
打包机是 Win11，收进去的就是 Win11 版的 `ucrtbase.dll`（10.0.26100）——
而那个版本要用这些组件：

```
api-ms-win-core-sysinfo-l1-2-0.dll      ← Win7 上不存在
api-ms-win-core-kernel32-legacy-l1-1-1.dll
api-ms-win-core-fibers-l1-1-1.dll
```

Win7 里没有这套机制（它是 Win8 才引入的），PyInstaller 也没把它们一起收进来。
于是 exe 在 Win7 上加载运行库就断在这儿。

**更麻烦的是**：这堆 DLL 跟在 exe 旁边，优先级高于系统自己那份。所以**就算
机器已经打过 KB2999226 补丁**（装过 Python 3.7 的机器就有），也会被包里这份
顶掉 —— 装补丁救不回来。

---

## 二、改法：换成微软自己的"发给老系统"那一份

Windows SDK 里有一份 UCRT 重分发包（`Redist\ucrt\DLLs\x86|x64`，版本
10.0.10240），那正是 KB2999226 装进 Win7 的东西：只依赖 Win7 有的组件，
而它缺的那几个（file-l1-2-0、synch-l1-2-0 等）重分发包里自带存根。一共 1.9 MB。

打包时把 PyInstaller 收进来的那份**换掉**：

```
打包前：ucrtbase.dll 10.0.26100.8875   ← 打包机的 System32，Win7 上崩
打包后：ucrtbase.dll 10.0.10240.16384  ← SDK 重分发包，兼容 Win7
```

命令加一个 `--ucrt` 就行：

```bash
python build.py --python <3.8> --server 111.170.33.3:3315 --ucrt
```

产物文件名多一个「内置运行库」，**不覆盖原来的 exe**：

```
考试客户端-32位-内置运行库@111.170.33.3_3315.exe    8.5 MB   ← 机房发这个
考试客户端-64位-内置运行库@111.170.33.3_3315.exe    9.5 MB
考试客户端-32位@111.170.33.3_3315.exe               旧的，留着对比
考试客户端-64位@111.170.33.3_3315.exe
```

换完的包在 Win7 到 Win11 上都能跑 —— 重分发包本来就是为"一份程序发到所有
Windows"准备的。

---

## 三、加一道静态检查，别再让它溜过去

**自检过不了关**：自检是在打包机上跑的，那台机器什么都有，缺的组件只在 Win7
上才暴露。所以打包最后多一步静态检查（`tools/查Win7依赖.py`）：

把包里每个 DLL/PYD 的导入表摊开，凡是 `api-ms-win-*` 就看它在不在包里。
在包里没问题（跟着 exe 一起解包，Win7 也能加载）；不在包里的，Win7 系统里
也没有，就是起不来的原因。

拿旧包试了一遍，它准确报出了学生机上那条错：

```
ucrtbase.dll：10.0.26100.8875　← 打包机的 System32，**Win7 上会崩**
**Win7 上会缺 5 个 api-set**：
   api-ms-win-core-sysinfo-l1-2-0.dll             ← ucrtbase.dll
   api-ms-win-core-kernel32-legacy-l1-1-1.dll     ← ucrtbase.dll
   ...
```

加了 `--ucrt` 之后这一步过不了就**不出包**。

---

## 验证

- 两版都：自检通过、连上线上教师端、单独拷进空文件夹能跑、跑完不留文件
- 静态检查：新包「每个 api-set 都自带，没有缺的」；旧包准确报出学生机那条错
- 从 exe 里把 `ucrtbase.dll` 抠出来核对：版本 10.0.10240.16384，
  不再引用 `api-ms-win-core-sysinfo-l1-2-0.dll`

## 升级注意

**机房统一发「内置运行库」那两个**，学生机不用装任何补丁。不确定是什么机器
就发 32 位那份（32 位和 64 位 Windows 都能跑）。
